## 1. TypeScript 개요

**JavaScript에 데이터 타입(Type) 문법을 추가한 언어**

- Microsoft에서 개발, `.ts` / `.tsx` 확장자 사용
- 최종적으로 **JavaScript로 변환**되어 브라우저에서 실행
- 타입 정보는 컴파일 시 검사 후 JS 변환 시 대부분 제거됨

**사용 이유**

| 이유 | 설명 |
|------|------|
| 오류 조기 발견 | 실행 전 컴파일 단계에서 타입 오류 감지 |
| 가독성 향상 | 변수·함수의 타입을 명시해 코드 의도가 명확 |
| 유지보수 편리 | 대규모 프로젝트에서 팀원 간 코드 파악이 쉬움 |
| IDE 자동완성 | WebStorm / VSCode에서 타입 기반 자동 추론 지원 |

---

## 2. 동작 원리

```
TypeScript 작성 (.ts / .tsx)
        │
        ▼
컴파일 (타입 검사)
        │  타입 오류 발견 → 실행 전 에러 출력
        ▼
JavaScript 변환 (.js / .jsx)
        │  타입 정보 제거 → 순수 JS
        ▼
브라우저 실행
```

> TypeScript는 JavaScript의 **상위 집합**  
> → 기존 JS 코드를 그대로 사용하면서 점진적으로 타입 추가 가능

## 3. 핵심 데이터 타입

### 1) 기본 타입

```typescript
let userName: string  = "홍길동"
let age:      number  = 20        // 정수 / 실수 구분 없음
let score:    number  = 80.5
let isLogin:  boolean = false
```

### 2) 배열

```typescript
// 두 가지 선언 방식 (동일)
let names: string[]        = ["홍길동", "심청이"]
let names: Array<string>   = ["홍길동", "심청이"]

let numbers: number[]      = [1, 2, 3]
```

### 3) Tuple - 순서와 타입이 고정된 배열

```typescript
// Oracle Row 개념과 유사 - 순서와 타입 모두 고정
let user: [string, number] = ["홍길동", 25]
```

### 4) Union - 여러 타입 허용

```typescript
// | 로 여러 타입 중 하나 선택
let value: string | number | boolean
value = "홍길동"  // ✅
value = 1000      // ✅
```

### 5) Literal Type - 특정 값만 허용

```typescript
type Sex = "남자" | "여자"
let s: Sex = "남자"   // "남자" 또는 "여자" 외 값 불가
```

### 6) any / unknown

```typescript
let data: any     // 타입 무시 (JS와 동일, 지양 권장)
let data: unknown // any보다 안전 - 사용 전 타입 확인 필요
```

### 7) null / undefined

```typescript
let val: null      = null
let val: undefined = undefined

// null 허용 Union 패턴 (실무 자주 사용)
let user: User | null = null
```

### 8) void - 반환값 없는 함수

```typescript
function printLog(): void {
    console.log("Hello TypeScript")
    // return 없음
}
```

**타입 요약표**

| 타입 | 설명 | 예시 |
|------|------|------|
| `string` | 문자열 | `"홍길동"` |
| `number` | 숫자 (정수/실수 통합) | `20`, `80.5` |
| `boolean` | 참/거짓 | `true`, `false` |
| `string[]` | 문자열 배열 | `["A", "B"]` |
| `[string, number]` | Tuple | `["홍길동", 25]` |
| `A \| B` | Union | `string \| number` |
| `any` | 타입 무시 | - |
| `void` | 반환 없음 | 함수 반환 타입 |
| `null \| Type` | null 허용 | `User \| null` |

## 4. interface & type

### 1) interface - 객체 구조 정의 (VO 역할)

```typescript
interface User {
    no:    number
    name:  string
    email?: string   // ? = 선택 속성 (null 허용)
}

const user1: User = { no: 1, name: "홍길동" }              // email 없어도 OK
const user2: User = { no: 2, name: "심청이", email: "a@b.com" }
```

### 2) type - interface와 유사, Union 표현에 강점

```typescript
type User = {
    no:    number
    name:  string
    email?: string
}

// Union 상태 표현 - React 상태 관리에서 자주 사용
type Status = "READY" | "RUNNING" | "END"
```

### 3) interface vs type 비교

| 구분 | interface | type |
|------|-----------|------|
| 객체 구조 정의 | ✅ | ✅ |
| 확장(상속) | ✅ `extends` | ✅ `&` |
| Union 표현 | 제한적 | ✅ 자유로움 |
| React 컴포넌트 Props | 주로 사용 | 사용 가능 |

> 실무에서 **객체 구조 → interface**, **Union / 상태값 → type** 으로 구분해서 사용하는 경우가 많음

## 5. 함수 타입

```typescript
// 선언적 함수
function add(a: number, b: number): number {
    return a + b
}

// 화살표 함수 (익명 함수 - 데이터처럼 사용)
const add2 = (a: number, b: number): number => a + b

// void 함수
const printName = (name: string): void => {
    console.log(name)
}
```

**함수 선언 방식 비교**

```typescript
function func(): number {}       // 선언적 함수
const func = (): number => {}    // 화살표 함수 (익명)
const func = function(): number {} // 함수 표현식
```

## 6. Generic

**타입을 나중에 결정** - 재사용 가능한 타입 안전한 함수/컴포넌트 구현

```typescript
// <T> : 호출 시 타입 결정
function getData<T>(data: T): T {
    return data
}

const res1 = getData<string>("Hello")  // T = string
const res2 = getData<number>(100)      // T = number
```

Java의 `ArrayList<String>`, `List<FoodVO>` 와 동일한 개념

**React에서 Generic 활용**

```typescript
// useState에 타입 지정
const [list, setList]     = useState<Food[]>([])
const [detail, setDetail] = useState<Food | null>(null)
const [count, setCount]   = useState<number>(0)
```

## 7. React + TypeScript 연동

### 1) 파일 확장자

| 확장자 | 용도 |
|--------|------|
| `.ts` | 순수 TypeScript (로직, 유틸리티) |
| `.tsx` | TypeScript + JSX (React 컴포넌트) |

### 2) Props 타입 정의

```typescript
// interface로 Props 구조 정의
interface FoodCardProps {
    no:      number
    name:    string
    address: string
    poster?: string   // 선택 속성
}

const FoodCard = ({ no, name, address, poster }: FoodCardProps) => {
    return (
        <div>
            <h3>{name}</h3>
            <p>{address}</p>
        </div>
    )
}
```

### 3) API 응답 타입 정의

```typescript
// 서버 응답 데이터 구조를 interface로 정의
interface Food {
    no:      number
    name:    string
    address: string
    price:   number | null   // DB null 허용 컬럼
    poster?: string
}

// axios 응답에 Generic 적용
const [list, setList] = useState<Food[]>([])

useEffect(() => {
    axios.get<Food[]>('/api/food/list')
        .then(res => setList(res.data))
}, [])
```

### 4) DB null 값 처리 패턴

```typescript
// Oracle에서 null이 올 수 있는 컬럼 처리
interface Food {
    price: number | null   // null 허용
}

// 화면 출력 시 null 체크
{food.price ? food.price.toLocaleString() + '원' : '가격 미정'}
```

> Jackson(Spring Boot)이 `SELECT`로 가져온 null 컬럼을 JSON으로 전송할 때  
> TypeScript에서 `타입 | null` 로 명시해야 타입 오류 없이 처리 가능

### 5) JavaScript vs TypeScript 비교

```javascript
// JavaScript
let name = "홍길동"     // 타입 없음, 나중에 숫자로 바꿔도 오류 없음
```

```typescript
// TypeScript
let name: string = "홍길동"  // string 고정
name = 100  // ❌ 컴파일 오류 → 실행 전 감지
```

### 배운 점
- TypeScript의 핵심 가치는 실행 전에 타입 오류를 잡아주는 것으로, 특히 서버 API 응답 데이터 구조를 interface로 정의하면 잘못된 필드 접근을 컴파일 단계에서 방지할 수 있음을 이해함
- Oracle DB에서 null이 올 수 있는 컬럼은 `number | null` 처럼 Union으로 표현해야 런타임 오류 없이 처리할 수 있다는 실무 패턴을 이해함
- `useState<Food | null>(null)` 처럼 Generic으로 상태 타입을 지정하면 `setDetail`에 잘못된 타입의 값을 넣을 때 즉시 오류가 나서 디버깅이 훨씬 쉬워짐을 이해함
- TypeScript는 최종적으로 JavaScript로 변환되므로 기능을 추가하는 것이 아니라 **개발 중 오류 방지와 가독성**을 위한 도구임을 이해함
