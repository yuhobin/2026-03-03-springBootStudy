## 2. AWS EC2 기본 환경 세팅

### 1) 패키지 업데이트

```bash
sudo apt update
sudo apt upgrade -y
```

### 2) Java 21 설치

```bash
sudo apt install openjdk-21-jdk -y
```

### 3) Java 환경변수 설정

```bash
# bashrc 파일 편집
sudo nano ~/.bashrc
```

파일 맨 아래에 추가:

```bash
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
export PATH=$PATH:$JAVA_HOME/bin
```

저장 후 나오기: `Ctrl+O` → `Enter` → `Ctrl+X`

```bash
# 변경 사항 적용 및 확인
source ~/.bashrc
echo $JAVA_HOME
```

## 3. SSH 키 생성 및 GitHub 연결

GitHub Actions가 AWS EC2에 SSH로 접속할 수 있도록 키를 생성하고 등록한다.

### 1) SSH 키 생성

```bash
cd ~/.ssh
ls -al                          # 기존 키 확인

# ed25519 알고리즘으로 키 생성
ssh-keygen -t ed25519 -b 4096 -C "이메일주소"
ls -al                          # id_ed25519 (개인키), id_ed25519.pub (공개키) 생성 확인
```

### 2) 공개키를 authorized_keys에 등록 (EC2 자신이 허용)

```bash
cat id_ed25519.pub >> authorized_keys
cat authorized_keys             # 등록 확인
```

### 3) 개인키를 GitHub Secrets에 등록

```bash
# 개인키 내용 출력 → 전체 복사해서 GitHub Secrets에 등록
cat id_ed25519
```

출력 결과 전체 (BEGIN ~ END 포함)를 복사:

```
-----BEGIN OPENSSH PRIVATE KEY-----
(키 내용)
-----END OPENSSH PRIVATE KEY-----
```

→ GitHub Repository → Settings → Secrets → `SERVER_SSH_KEY`로 등록

**SSH 키 구조**

| 파일 | 종류 | 용도 |
|------|------|------|
| `id_ed25519` | 개인키 | GitHub Secrets에 등록 (Actions가 EC2 접속 시 사용) |
| `id_ed25519.pub` | 공개키 | EC2 `authorized_keys`에 등록 (접속 허용) |

## 4. Docker 설치

### 1) 사전 패키지 설치

```bash
sudo apt install ca-certificates curl gnupg lsb-release
```

### 2) Docker 공식 GPG 키 및 저장소 등록

```bash
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg

echo "deb [arch=$(dpkg --print-architecture) \
  signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] \
  https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt update
```

### 3) Docker 엔진 설치 및 확인

```bash
sudo apt install docker-ce docker-ce-cli containerd.io

sudo systemctl status docker    # active(running) 확인
sudo systemctl enable docker    # 서버 재시작 시 자동 실행 설정
```

### 4) Docker Compose 설치

```bash
sudo curl -L "https://github.com/docker/compose/releases/download/1.28.2/docker-compose-$(uname -s)-$(uname -m)" \
  -o /usr/local/bin/docker-compose

sudo chmod +x /usr/local/bin/docker-compose   # 실행 권한 부여
```

### 5) sudo 없이 docker 사용 설정

```bash
sudo usermod -aG docker ubuntu  # ubuntu 사용자를 docker 그룹에 추가

# docker.sock 권한 변경
cd /var/run
sudo chmod +x docker.sock

newgrp docker                   # 그룹 변경 즉시 적용 (재로그인 없이)
```

> `newgrp docker` 후부터 `sudo` 없이 `docker` 명령 사용 가능

## 6. GitHub Actions 자동 배포 (deploy.yml)

프로젝트 루트의 `.github/workflows/deploy.yml`에 작성

### 1) 전체 배포 흐름

```
git push (main)
    │
    ▼
GitHub Actions (ubuntu-latest 임시 환경)
    │
    ├── Checkout → JDK 21 세팅
    ├── Gradle 빌드 (.jar 생성)
    ├── Docker 이미지 빌드 → Docker Hub push
    ├── SSH 키 설정 → EC2 접속
    ├── .env 환경변수 파일 생성
    ├── docker-compose.yml SCP 전송
    └── docker-compose pull & up
    │
    ▼
AWS EC2 : 최신 이미지로 컨테이너 재시작 → 배포 완료
```

### 2) 단계별 핵심 설명

**빌드 & Docker Hub 업로드**

```yaml
- name: Set gradlew permission
  run: chmod +x ./gradlew

- name: Build with Gradlew
  run: ./gradlew clean build -x test      # 테스트 생략

- name: Login DockerHub
  run: |
    echo "${{ secrets.DOCKER_PASSWORD }}" | \
    docker login -u "${{ secrets.DOCKER_USERNAME }}" --password-stdin

- name: Build Docker Image
  run: docker build -t ${{ secrets.DOCKER_USERNAME }}/last-app:latest .

- name: Push Docker Image
  run: docker push ${{ secrets.DOCKER_USERNAME }}/last-app:latest
```

**EC2 SSH 연결**

```yaml
- name: Set SSH key Permission
  run: |
    mkdir -p ~/.ssh
    echo "${{ secrets.SERVER_SSH_KEY }}" > ~/.ssh/id_ed25519
    chmod 600 ~/.ssh/id_ed25519       # 소유자만 읽기 (SSH 보안 요구사항)

- name: Add SSH Key
  uses: webfactory/ssh-agent@v0.5.3
  with:
    ssh-private-key: ${{ secrets.SERVER_SSH_KEY }}

- name: Add Known_hosts
  run: ssh-keyscan -H EC2_IP >> ~/.ssh/known_hosts
```

**DB 환경변수 파일 생성 및 배포**

```yaml
- name: 환경설정
  run: |
    ssh ubuntu@EC2_IP << EOF
      mkdir -p ~/app && cd ~/app
      rm -f .env
      echo "DB_URL=${{ secrets.DB_URL }}"           >> ~/app/.env
      echo "DB_USERNAME=${{ secrets.DB_USERNAME }}" >> ~/app/.env
      echo "DB_PASSWORD=${{ secrets.DB_PASSWORD }}" >> ~/app/.env
      chmod 600 ~/app/.env
    EOF

- name: SCP docker-compose
  run: |
    ssh ubuntu@EC2_IP "mkdir -p /home/ubuntu/app"
    scp docker-compose.yml ubuntu@EC2_IP:/home/ubuntu/app/docker-compose.yml

- name: Deploy
  run: |
    ssh ubuntu@EC2_IP << 'EOF'
      cd /home/ubuntu/app
      docker-compose down       # 기존 컨테이너 종료
      docker-compose pull       # 최신 이미지 다운로드
      docker-compose up -d      # 백그라운드 재시작
    EOF
```

## 7. GitHub Secrets 등록

```
GitHub Repository → Settings → Secrets and variables → Actions → New repository secret
```

| Secret 키 | 내용 |
|-----------|------|
| `DOCKER_USERNAME` | Docker Hub 사용자명 |
| `DOCKER_PASSWORD` | Docker Hub 비밀번호 |
| `SERVER_SSH_KEY` | EC2 개인키 전체 (`cat id_ed25519` 출력 결과) |
| `DB_URL` | 데이터베이스 연결 URL |
| `DB_USERNAME` | DB 사용자명 |
| `DB_PASSWORD` | DB 비밀번호 |

> 모든 민감 정보는 코드에 직접 작성하지 않고 Secrets로 관리해 `${{ secrets.키명 }}`으로 참조

- ed25519 SSH 키 생성 → 공개키 `authorized_keys` 등록 → 개인키 GitHub Secrets 등록
- Docker / Docker Compose 설치 및 권한 설정
- Kafka 컨테이너 Docker로 실행
- GitHub Actions deploy.yml 작성 → push 트리거로 EC2 자동 배포 확인

### 배운 점
- SSH 키 쌍에서 공개키는 EC2 `authorized_keys`에, 개인키는 GitHub Secrets에 등록하는 구조로 GitHub Actions가 EC2에 안전하게 접속할 수 있음을 이해함
- `sudo usermod -aG docker ubuntu` + `newgrp docker` 로 `sudo` 없이 docker 명령을 사용할 수 있게 되고, docker.sock 권한도 함께 변경해야 한다는 것을 실습으로 확인함
- `chmod 600`은 SSH 키와 `.env` 파일처럼 민감한 파일에 소유자만 읽기 권한을 부여하는 리눅스 보안 설정으로, SSH 연결 시 필수 요구사항임을 이해함
- GitHub Actions의 `ubuntu-latest`는 임시 환경이고, 실제 운영 서버(EC2)는 SSH로 원격 접속해 명령을 실행하는 방식으로 배포가 이루어짐을 이해함
