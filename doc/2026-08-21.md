## 1. Kubernetes 개요

여러 컨테이너(Docker)를 자동으로 배포·관리·확장하는 **컨테이너 오케스트레이션** 플랫폼

**Docker vs Kubernetes**

| 구분 | Docker | Kubernetes |
|------|--------|-----------|
| 역할 | 컨테이너 생성·실행 | 컨테이너 자동 관리·배포·확장 |
| 범위 | 단일 컨테이너 | 여러 컨테이너 클러스터 관리 |
| 장애 처리 | 수동 | 자동 재시작 / 복구 |
| 확장 | 수동 | 자동 스케일링 |

> Docker가 컨테이너를 만드는 도구라면, Kubernetes는 그 컨테이너들을 **관리하는 지휘관** 역할

---

## 2. 핵심 용어

```
클러스터 (Kubernetes가 관리하는 전체 시스템)
    │
    ▼
노드 (각 서버 컴퓨터)
    │
    ▼
파드 (실행 가능한 가장 작은 단위)
    │
    ▼
컨테이너 (실제 실행 중인 앱 = Docker 컨테이너)
```

| 용어 | 설명 |
|------|------|
| **클러스터** | Kubernetes가 관리하는 전체 컴퓨터 묶음. Minikube에서는 1개 |
| **노드** | 클러스터 안의 각 서버 (컨테이너가 실행되는 물리/가상 머신) |
| **파드 (Pod)** | 컨테이너를 감싸는 실행 단위. 쿠버네티스의 최소 배포 단위 |
| **컨테이너** | 파드 안에서 실제 실행되는 Docker 컨테이너 |
| **kubectl** | Kubernetes에 명령을 내리는 CLI 도구 |
| **Service** | 파드를 외부에 노출하는 네트워크 설정 |
| **Deployment** | 파드 배포 방식과 복제 수를 정의하는 설정 파일 |

## 3. Minikube - 로컬 쿠버네티스

**Minikube 사용 목적**

- 비용 없이 로컬 환경에서 Kubernetes 학습·테스트 가능
- Docker + DockerHub 이미지를 그대로 활용
- 실제 Kubernetes 환경과 동일한 동작 방식

```
내 컴퓨터
    │
    ▼
Minikube (가상 클러스터)
    │
    ▼
Kubernetes
    │
    ▼
파드 → 컨테이너 실행
```

## 4. Docker → Kubernetes 배포 흐름

### 1) Docker 이미지 빌드 & Hub 업로드

```bash
# 이미지 빌드
docker build -t 이미지명 .

# DockerHub 태그 추가 (허브명/이미지명 형식)
docker tag 이미지명 허브명/이미지명

# DockerHub 로그인 & 업로드
docker login -u 허브명
docker push 허브명/이미지명
```

### 2) deployment.yaml 작성

Kubernetes에 파드를 어떻게 배포할지 정의하는 설정 파일

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: food-app
spec:
  replicas: 1                           # 파드 수
  selector:
    matchLabels:
      app: food-app
  template:
    metadata:
      labels:
        app: food-app
    spec:
      containers:
        - name: food-app
          image: 허브명/이미지명          # DockerHub에서 pull
          ports:
            - containerPort: 8080
---
apiVersion: v1
kind: Service
metadata:
  name: food-app-service
spec:
  type: NodePort
  selector:
    app: food-app
  ports:
    - port: 8080
      targetPort: 8080
```

### 3) Minikube 배포 실행

```bash
# 1. Minikube 시작
minikube start

# 2. 설정 파일 적용 (파드 생성)
kubectl apply -f ~/k8s/deployment.yaml

# 3. 파드 상태 확인
kubectl get pods
# Running 상태가 아닌 경우 로그 확인
kubectl logs 파드명

# 4. 서비스 확인
kubectl get svc

# 5. 브라우저에서 앱 실행
minikube service food-app-service
```

## 5. 주요 명령어

**Minikube**

| 명령어 | 설명 |
|--------|------|
| `minikube start` | 클러스터 시작 |
| `minikube stop` | 클러스터 중지 |
| `minikube status` | 클러스터 상태 확인 |
| `minikube dashboard` | 웹 UI 대시보드 실행 |
| `minikube service 서비스명` | 서비스 바로 실행 (브라우저 열기) |

**kubectl**

| 명령어 | 설명 |
|--------|------|
| `kubectl get nodes` | 노드 목록 확인 |
| `kubectl get pods` | 파드 목록 및 상태 확인 |
| `kubectl get svc` | 서비스 목록 확인 |
| `kubectl apply -f 파일명.yaml` | 설정 파일 적용 (배포) |
| `kubectl delete -f 파일명.yaml` | 설정 파일로 생성된 리소스 삭제 |
| `kubectl logs 파드명` | 파드 로그 확인 (에러 디버깅) |
| `kubectl describe pod 파드명` | 파드 상세 정보 확인 |

## 6. 실무 환경에서의 활용

실무에서는 서비스별로 서버를 분리하고 Kubernetes로 통합 관리한다.  
이 구조가 **MSA(Microservice Architecture)** 의 기반이 된다.

```
서버 1 - 게시판 서비스
서버 2 - 상품 서비스       ← Kubernetes 클러스터로 통합 관리
서버 3 - 회원 서비스
```

- 특정 서버에 트래픽이 몰리면 해당 파드만 자동으로 수를 늘림 (Auto Scaling)
- 파드가 다운되면 자동으로 재시작 (Self-Healing)
- 새 버전 배포 시 기존 파드를 유지하면서 점진적으로 교체 (Rolling Update)

> Minikube는 이 환경을 로컬에서 1개 클러스터로 시뮬레이션하는 학습 도구

### 배운 점
- Docker가 컨테이너를 만드는 도구라면 Kubernetes는 그 컨테이너들을 자동으로 관리·복구·확장하는 상위 개념임을 이해함
- `deployment.yaml`에 DockerHub 이미지 경로를 지정하면 Kubernetes가 자동으로 pull해서 파드를 실행하는 구조가 Docker Compose와 유사하지만 훨씬 강력한 클러스터 관리 기능을 제공함을 이해함
- 파드가 Running이 아닌 경우 `kubectl logs 파드명`으로 원인을 확인하는 디버깅 흐름을 이해함
- Minikube는 비용 없이 로컬에서 실제 Kubernetes와 동일한 환경을 테스트할 수 있어 학습 도구로 적합함을 이해함
