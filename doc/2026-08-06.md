## 1. Docker 개요

**프로그램을 통째로 상자(컨테이너)에 담아 어디서든 동일하게 실행**하는 도구

**기존 방식의 문제점**
- 설치 과정이 복잡하고 실수가 많음
- 사람마다 버전·설정이 달라 "내 PC에서는 되는데 팀원 PC에서는 안 됨" 현상 발생
- 설치 후 삭제도 번거로움

**Docker를 사용하면**
- 동일한 이미지를 사용하므로 누구의 PC든 동일한 환경으로 실행
- `docker rm` 한 줄로 깔끔하게 삭제
- 컨테이너가 독립된 상자이므로 MySQL 8.0 / 5.7 을 동시에 실행해도 충돌 없음

## 2. 핵심 개념

| 개념 | 설명 | 비유 |
|------|------|------|
| **Image** | 프로그램을 설치·설정한 완성본을 담은 파일 | 붕어빵 틀 |
| **Container** | 이미지로 실행 중인 인스턴스 | 붕어빵 틀로 찍어낸 붕어빵 |
| **Docker Hub** | 전 세계 이미지를 공유하는 저장소 | 프로그램 창고 |
| **Dockerfile** | 이미지를 만드는 설계 명세서 | 붕어빵 틀 제작 설명서 |
| **docker-compose.yml** | 여러 컨테이너를 한 번에 관리하는 설계도 | 공장 전체 운영 매뉴얼 |

## 3. 전체 배포 흐름

```
로컬 개발
    │  gradlew build → .jar 생성
    ▼
Dockerfile 작성
    │  docker build → 이미지 생성
    ▼
Docker Hub
    │  docker push → 이미지 업로드
    ▼
배포 서버 (Ubuntu)
    │  docker pull → 이미지 다운로드
    │  docker run  → 컨테이너 실행
    ▼
서비스 운영
```

## 5. Docker 설치

```bash
# 사전 패키지
sudo apt-get install ca-certificates curl gnupg lsb-release -y

# Docker 공식 GPG 키 등록
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg

# APT 저장소 추가
echo "deb [arch=$(dpkg --print-architecture) \
  signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] \
  https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 설치 및 확인
sudo apt update
sudo apt install docker-ce docker-ce-cli containerd.io -y
sudo systemctl status docker    # active(running) 이면 정상
```

## 6. 앱 빌드 & 이미지 배포

### 1) 앱 빌드

```bash
git clone https://github.com/계정/프로젝트명.git
cd 프로젝트명
sudo chmod +x gradlew
sudo ./gradlew build            # build/libs/*.jar 생성
```

### 2) Dockerfile 작성 (프로젝트 루트)

```dockerfile
FROM eclipse-temurin:21-jdk    # 베이스 이미지 (Java 21)
WORKDIR /app                   # 컨테이너 내 작업 디렉토리
COPY build/libs/*-SNAPSHOT.jar app.jar  # .jar 파일 복사
EXPOSE 8080                    # 외부에 노출할 포트
ENTRYPOINT ["java","-jar","app.jar"]    # 실행 명령
```

### 3) 이미지 빌드 & Docker Hub 배포

```bash
sudo docker login -u 사용자명              # Hub 로그인
sudo docker build -t food-app .           # 이미지 빌드
sudo docker tag food-app 사용자명/food-app # Hub 업로드용 태그 추가
sudo docker push 사용자명/food-app         # Hub에 업로드
```

> 태그 생략 시 `:latest` 자동 부여. 태그 추가는 삭제가 아닌 별칭으로 IMAGE ID는 동일하다.

## 7. 컨테이너 실행 & 관리

### 1) 실행

```bash
sudo docker pull 사용자명/food-app               # 이미지 다운로드
sudo docker run --name food-app -d -p 8080:8080 사용자명/food-app
#                               │   └─ 호스트포트:컨테이너포트
#                               └─ 백그라운드 실행
sudo docker ps                                   # 실행 중 컨테이너 확인
```

### 2) 생명주기 관리

```bash
sudo docker stop food-app      # 컨테이너 중지
sudo docker start food-app     # 컨테이너 재시작
sudo docker rm food-app        # 중지된 컨테이너 삭제
sudo docker rm -f food-app     # 실행 중인 컨테이너 강제 삭제
sudo docker rmi food-app       # 이미지 삭제
sudo docker images -a          # 로컬 이미지 목록 확인
```

## 8. Docker Compose

여러 컨테이너를 한 번에 정의하고 관리하는 도구

```bash
# 설치
sudo curl -L "https://github.com/docker/compose/releases/download/1.28.2/docker-compose-$(uname -s)-$(uname -m)" \
  -o /usr/local/bin/docker-compose
sudo chmod +x /usr/local/bin/docker-compose
```

**docker-compose.yml**

```yaml
version: "3"
services:
  app:
    image: 사용자명/food-app
    ports:
      - "8080:8080"
```

```bash
sudo docker compose up -d      # 백그라운드 실행
sudo docker compose down       # 컨테이너 종료 및 제거
```

> Docker Compose의 장점은 `docker run` 명령의 복잡한 옵션들을 yml 파일로 관리해서 **재현성과 가독성**이 높아진다는 점이다.

## 9. 방화벽 설정

```bash
sudo ufw allow 22/tcp          # SSH 먼저 허용 (필수 - 먼저 열지 않으면 SSH 세션이 끊김)
sudo ufw allow 8080            # 앱 포트 허용
sudo ufw enable                # 방화벽 활성화
sudo ufw status                # 적용 확인
```

> ⚠️ `ufw enable` 전에 반드시 22번 포트를 열어야 SSH 접속이 끊기지 않는다.

```bash
sudo ufw disable               # 방화벽 비활성화
sudo ufw delete allow 8080     # 허용 규칙 삭제
```

### 배운 점
- Docker가 해결하는 핵심 문제는 "환경 차이"로, 이미지 하나로 개발·테스트·운영 환경을 동일하게 만들 수 있다는 점에서 CI/CD 배포 안정성이 크게 높아짐을 이해함
- Dockerfile의 각 명령(`FROM`, `WORKDIR`, `COPY`, `EXPOSE`, `ENTRYPOINT`)이 이미지를 어떻게 레이어 단위로 구성하는지 이해함
- `docker run -p 8080:8080` 에서 앞은 호스트 포트, 뒤는 컨테이너 내부 포트로 포트 매핑이 이루어진다는 것을 이해함
- 방화벽 설정 시 SSH(22번) 포트를 먼저 열지 않으면 `ufw enable` 후 원격 접속이 차단된다는 것을 직접 확인함
