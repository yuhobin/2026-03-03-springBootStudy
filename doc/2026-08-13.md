## 1. Spring Boot 환경에서 Pinia 사용 방식

VSCode 기반 Vue 프로젝트와 달리, **Spring Boot(Thymeleaf/JSP) 환경에서는 CDN 방식으로 Pinia를 사용**한다.  
`npm` 설치 없이 HTML에 스크립트를 불러와 `Pinia` 전역 객체에서 `defineStore`를 구조분해해서 사용한다.

```javascript
// CDN 방식 : Pinia 전역 객체에서 직접 구조분해
const { defineStore } = Pinia
```

## 2. Store 설계 구조

맛집 리스트 + 페이징을 처리하는 Store 설계

```
food_store
    │
    ├── state          ← HTML에 바인딩되는 공유 데이터
    │     ├── list[]         맛집 목록
    │     ├── curpage        현재 페이지
    │     ├── totalpage      전체 페이지 수
    │     ├── startPage      페이지 범위 시작
    │     └── endPage        페이지 범위 끝
    │
    ├── getters        ← state를 가공해서 반환 (computed)
    │     └── range          startPage ~ endPage 배열 생성
    │
    └── actions        ← 서버 연동 / 상태 변경 (methods)
          ├── foodListData() 서버에서 목록 + 페이징 데이터 수신
          └── move(page)     페이지 이동 → foodListData 재호출
```

## 3. Store 코드 구성

### 1) 초기 state 분리 - initialState

```javascript
// state 초기값을 함수로 분리
// → Store를 초기화하거나 리셋할 때 재사용 가능
const initialState = () => ({
    list: [],
    curpage: 1,
    totalpage: 0,
    startPage: 0,
    endPage: 0
})
```

### 2) Store 생성

```javascript
const { defineStore } = Pinia

const useFoodStore = defineStore('food_store', {

    state: initialState,    // 초기 state 함수 연결

    // getters : state를 가공해서 반환 → computed와 동일
    // 페이지 범위 배열 생성 (startPage ~ endPage)
    getters: {
        range: (state) => {
            const arr = []
            for (let i = state.startPage; i <= state.endPage; i++) {
                arr.push(i)
            }
            return arr
        }
    },

    // actions : 서버 연동 및 상태 변경 → methods와 동일
    actions: {
        // 서버에서 목록 + 페이징 데이터 수신
        async foodListData() {
            const res = await api.get('/food/list_vue', {
                params: { page: this.curpage }
            })
            // 서버 응답 Map 데이터를 state에 반영
            this.list      = res.data.list
            this.curpage   = res.data.curpage
            this.totalpage = res.data.totalpage
            this.startPage = res.data.startPage
            this.endPage   = res.data.endPage
        },

        // 페이지 이동 : curpage 변경 후 목록 재조회
        move(page) {
            this.curpage = page
            this.foodListData()
        }
    }
})
```

### 3) this vs state 사용 시점

| 위치 | 사용 | 이유 |
|------|------|------|
| `getters` | `state.변수명` | 파라미터로 받은 state만 접근 가능 |
| `actions` | `this.변수명` | Store 전체(state + actions + getters)에 접근 가능 |

```javascript
// getters : state만 접근
range: (state) => { ... state.startPage ... }

// actions : this로 Store 전체 접근
async foodListData() { this.list = res.data.list }
move(page) { this.curpage = page; this.foodListData() }
```

## 4. 전체 데이터 흐름

```
HTML (페이지 버튼 클릭)
        │
        │  store.move(page)
        ▼
actions.move(page)
        │  curpage 변경 → foodListData() 재호출
        ▼
actions.foodListData()
        │  axios.get('/food/list_vue', { params: { page } })
        ▼
Spring Boot Controller
        │  페이징 처리 후 Map으로 응답
        │  { list, curpage, totalpage, startPage, endPage }
        ▼
state 갱신 (list, curpage, startPage, endPage ...)
        │
        ▼
getters.range 자동 재계산 (startPage ~ endPage 배열)
        │
        ▼
HTML 자동 갱신 (v-for로 목록 + 페이지 버튼 렌더링)
```

**서버 응답 데이터 구조 (Spring Boot → Map)**

| key | 설명 |
|-----|------|
| `list` | 맛집 목록 데이터 |
| `curpage` | 현재 페이지 |
| `totalpage` | 전체 페이지 수 |
| `startPage` | 페이지 범위 시작 번호 |
| `endPage` | 페이지 범위 끝 번호 |

### 배운 점
- VSCode 프로젝트와 달리 Spring Boot 환경에서는 `const { defineStore } = Pinia` 구조분해로 Pinia를 사용한다는 환경 차이를 이해함
- `getters`에서는 `state`를 파라미터로 받아 사용하고, `actions`에서는 `this`로 Store 전체에 접근한다는 사용 위치별 차이를 이해함
- 페이지 이동 시 `move(page)` 하나로 curpage 변경과 데이터 재조회를 처리하는 구조가 컴포넌트 코드를 단순하게 유지하는 핵심임을 이해함
- 서버에서 Map으로 페이징 관련 데이터를 한 번에 응답하고 state에 한 번에 반영하는 방식이 효율적임을 이해함
