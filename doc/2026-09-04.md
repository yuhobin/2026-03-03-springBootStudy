## 1. PostgreSQL 개요

오픈소스 관계형 DB로, 확장성이 뛰어나 **AI / 벡터 검색** 분야에서 활발히 사용되고 있다.

- 무료 오픈소스 (Oracle은 유료)
- JSON, 배열, 벡터 등 **다양한 데이터 타입** 지원
- `pgVector` 확장 모듈로 Vector 유사도 검색 가능
- 이 프로젝트에서는 Oracle(원본 데이터)의 **서브 DB**로 Vector 데이터 저장 전용으로 활용

## 2. Oracle vs PostgreSQL 비교

| 구분 | Oracle | PostgreSQL |
|------|--------|-----------|
| 라이선스 | 유료 (상용) | 무료 (오픈소스) |
| 주요 사용처 | 대기업, 금융, 공공기관 | 스타트업, AI, 클라우드 |
| Auto Increment | `SEQUENCE` / `NEXTVAL` | `SERIAL` / `BIGSERIAL` |
| 문자열 함수 | `NVL()` | `COALESCE()` |
| 페이징 | `ROWNUM` | `LIMIT / OFFSET` |
| 날짜 함수 | `SYSDATE` | `NOW()` |
| 대소문자 | 기본 대문자 | 기본 소문자 |
| JSON 지원 | 제한적 | ✅ 네이티브 지원 |
| Vector 지원 | ❌ | ✅ pgVector 확장 |

## 3. 문법 차이

### 1) Auto Increment (PK 자동 증가)

```sql
-- Oracle
CREATE SEQUENCE recipe_seq START WITH 1 INCREMENT BY 1;
INSERT INTO recipe VALUES (recipe_seq.NEXTVAL, ...);

-- PostgreSQL
CREATE TABLE recipe (
    id SERIAL PRIMARY KEY,   -- 자동 증가
    ...
);
```

### 2) NULL 처리

```sql
-- Oracle
SELECT NVL(content, '없음') FROM recipe;

-- PostgreSQL
SELECT COALESCE(content, '없음') FROM recipe;
```

### 3) 페이징

```sql
-- Oracle
SELECT * FROM recipe WHERE ROWNUM <= 5;

-- PostgreSQL
SELECT * FROM recipe LIMIT 5 OFFSET 0;
```

### 4) 날짜

```sql
-- Oracle
SELECT SYSDATE FROM DUAL;

-- PostgreSQL
SELECT NOW();
```

### 5) 문자열 연결

```sql
-- Oracle
SELECT '레시피:' || recipe_name FROM recipe;

-- PostgreSQL (동일하게 || 사용 가능)
SELECT '레시피:' || recipe_name FROM recipe;
-- 또는 CONCAT 함수
SELECT CONCAT('레시피:', recipe_name) FROM recipe;
```

## 4. pgVector - AI Vector 저장소

### 1) pgVector 설치 및 활성화

```sql
-- PostgreSQL에 pgVector 확장 설치
CREATE EXTENSION IF NOT EXISTS vector;
```

### 2) Vector 컬럼을 포함한 테이블 생성

```sql
CREATE TABLE recipe_vector (
    id         SERIAL PRIMARY KEY,
    recipe_id  INT,                        -- Oracle recipe 테이블 FK
    content    TEXT,                       -- 원본 텍스트 (청크)
    embedding  vector(768)                 -- 벡터 차원 수 (모델마다 다름)
);
```

> `vector(768)` : Gemini Embedding 모델의 출력 차원 수. 사용하는 모델에 따라 차원이 다르며 저장 시와 검색 시 반드시 동일한 모델 사용

### 3) Vector 데이터 삽입

```sql
INSERT INTO recipe_vector (recipe_id, content, embedding)
VALUES (1, '닭고기 200g, 감자 2개...', '[0.12, 0.87, 0.34, ...]');
```

### 4) Cosine Distance 유사도 검색

```sql
-- 입력 벡터와 가장 유사한 레시피 검색
SELECT recipe_id, content,
       embedding <=> '[0.11, 0.85, 0.33, ...]' AS distance
FROM recipe_vector
ORDER BY distance ASC
LIMIT 5;
```

**pgVector 연산자**

| 연산자 | 거리 방식 | 설명 |
|--------|---------|------|
| `<=>` | Cosine Distance | 방향 유사도 (텍스트 의미 비교에 적합) |
| `<->` | L2 Distance (유클리드) | 절대 거리 |
| `<#>` | Inner Product | 내적 |

> 텍스트 의미 비교에는 `<=>` (Cosine Distance) 사용이 일반적

### 5) 인덱스 생성 (검색 성능 향상)

```sql
-- 대용량 벡터 검색 시 인덱스 추가
CREATE INDEX ON recipe_vector USING ivfflat (embedding vector_cosine_ops)
WITH (lists = 100);
```

## 5. Spring Boot 연동

### 1) build.gradle 의존성

```gradle
// PostgreSQL 드라이버
implementation 'org.postgresql:postgresql'

// pgVector Spring AI 지원
implementation 'org.springframework.ai:spring-ai-pgvector-store-spring-boot-starter'
```

### 2) application.yml 설정

```yaml
spring:
  datasource:
    # Oracle (메인 DB)
    url: jdbc:oracle:thin:@localhost:1521:xe
    username: sist
    password: sist

  # PostgreSQL (Vector DB)
  ai:
    vectorstore:
      pgvector:
        url: jdbc:postgresql://localhost:5432/vectordb
        username: postgres
        password: postgres
```

### 3) MyBatis Mapper - Vector 삽입

```java
// pgVector 삽입 쿼리 (MyBatis)
@Insert("INSERT INTO recipe_vector (recipe_id, content, embedding) " +
        "VALUES (#{recipeId}, #{content}, #{embedding}::vector)")
void insertVector(RecipeVectorVO vo);

// 유사 레시피 검색
@Select("SELECT recipe_id, content, " +
        "embedding <=> #{queryVector}::vector AS distance " +
        "FROM recipe_vector ORDER BY distance ASC LIMIT 5")
List<RecipeVectorVO> findSimilarRecipe(@Param("queryVector") String queryVector);
```

### 배운 점
- PostgreSQL은 Oracle과 문법이 유사하지만 `SERIAL`, `COALESCE`, `LIMIT/OFFSET`, `NOW()` 등 주요 함수명이 다르며, 두 DB를 동시에 사용할 때 문법을 혼동하지 않는 것이 중요함을 이해함
- pgVector의 `<=>` 연산자가 Cosine Distance를 계산해 텍스트 의미 유사도를 측정하며, 값이 작을수록 유사한 레시피임을 이해함
- 이 프로젝트에서 Oracle은 레시피 원본 데이터를, PostgreSQL+pgVector는 벡터 검색 전용으로 역할을 분리해 각 DB의 강점을 최대한 활용하는 구조임을 이해함
