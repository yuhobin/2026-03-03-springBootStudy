## 1. 관련 기술 개요

| 기술 | 역할 |
|------|------|
| **WebSocket** | 서버 ↔ 클라이언트 실시간 양방향 통신 기술 |
| **STOMP** | WebSocket 위에서 동작하는 메시지 프로토콜 (규칙 정의) |
| **SockJS** | WebSocket 미지원 환경에서 HTTP 기반으로 자동 대체하는 라이브러리 |

```
클라이언트
    │  SockJS (전화선 역할 - 연결 담당)
    ▼
WebSocket 연결
    │  STOMP (통신 규칙 - 송수신 프로토콜)
    ▼
메시지 브로커
    │  topic / queue 목적지로 라우팅
    ▼
구독 중인 클라이언트에게 전달
```

## 2. WebSocket vs HTTP

| 구분 | HTTP | WebSocket |
|------|------|-----------|
| 연결 방식 | 요청마다 연결·해제 (일회성) | 한 번 연결 후 지속 유지 |
| 통신 방향 | 단방향 (클라이언트 → 서버) | 양방향 (서버 ↔ 클라이언트) |
| 주요 용도 | 일반 웹 요청 | 실시간 채팅, 알림, AI 스트리밍 |

> AI 응답처럼 데이터를 스트리밍으로 받아야 하는 경우에도 WebSocket이 활용된다.

## 3. STOMP 동작 흐름

STOMP는 WebSocket 위에서 **목적지(destination) 기반으로 메시지를 발행·구독**하는 프로토콜이다.

**4가지 핵심 동작**

| 동작 | 설명 |
|------|------|
| `connect` | WebSocket 연결 수립 |
| `send` | 특정 목적지로 메시지 발행 |
| `subscribe` | 특정 목적지의 메시지 수신 |
| `disconnect` | 연결 종료 |

**목적지(Destination) 구분**

| 목적지 | 용도 |
|--------|------|
| `/topic/...` | 전체 브로드캐스트 (구독자 전원에게 전송) |
| `/queue/...` | 특정 사용자에게만 전송 (1:1 개인 메시지) |
| `/app/...` | 클라이언트 → 서버로 메시지 발행 시 prefix |

## 4. 서버 설정

```java
@Configuration
@EnableWebSocketMessageBroker   // STOMP 기반 WebSocket 활성화
public class WebSocketConfig implements WebSocketMessageBrokerConfigurer {

    @Override
    public void registerStompEndpoints(StompEndpointRegistry registry) {
        registry.addEndpoint("/ws-chat")          // 클라이언트 접속 URI
                .setAllowedOriginPatterns("*")    // 모든 클라이언트 접속 허용
                .withSockJS();                    // SockJS 폴백 활성화
    }

    @Override
    public void configureMessageBroker(MessageBrokerRegistry registry) {
        registry.enableSimpleBroker("/topic", "/queue"); // 구독 prefix (메시지 수신)
        registry.setApplicationDestinationPrefixes("/app"); // 발행 prefix (메시지 송신)
    }
}
```

> 실제 운영 환경에서는 `setAllowedOriginPatterns("*")` 대신 허용할 도메인을 명시적으로 지정해야 한다.

## 5. 메시지 전송 방식 - 전체 / 개인

### 1) 전체 브로드캐스트 - /topic

```
클라이언트 → stompClient.send("/app/chat.send")
                    │
              @MessageMapping("/chat.send")
                    │
              sendMessage() 실행
                    │
              @SendTo("/topic/public")
                    │
              /topic/public 구독자 전원에게 전송
```

```java
@MessageMapping("/chat.send")
@SendTo("/topic/public")
public ChatMessage sendMessage(ChatMessage message) {
    return message;   // 반환값이 /topic/public 구독자 전체에게 전달
}
```

### 2) 개인 메시지 - /queue

```
클라이언트 → stompClient.send("/app/chat.private")
                    │
              @MessageMapping("/chat.private")
                    │
              privateMessage() 실행
                    │
              message.getReceiver() 확인 (받는 사람 id)
                    │
              /queue/private/{receiverId} 구독자에게만 전송
```

```java
@MessageMapping("/chat.private")
public void privateMessage(ChatMessage message, SimpMessageHeaderAccessor headerAccessor) {
    // 받는 사람이 구독 중인 목적지로만 전송
    messagingTemplate.convertAndSend(
        "/queue/private/" + message.getReceiver(), message
    );
}
```

### 3) 전체 vs 개인 비교

| 구분 | 전체 브로드캐스트 | 개인 메시지 |
|------|----------------|-----------|
| 목적지 | `/topic/public` | `/queue/private/{userId}` |
| 대상 | 구독한 전원 | 특정 사용자 1명 |
| 서버 어노테이션 | `@SendTo` | `messagingTemplate.convertAndSend()` |
| 사용 예 | 공개 채팅방 | 1:1 채팅, 개인 알림 |

## 6. 클라이언트 연결 흐름

```javascript
// 1. SockJS로 WebSocket 연결
let socket = new SockJS('/ws-chat');        // 서버 EndPoint 연결
stompClient = Stomp.over(socket);           // STOMP 프로토콜 적용

// 2. 연결 수립
stompClient.connect({}, function(frame) {

    // 3. 전체 채팅 구독
    stompClient.subscribe('/topic/public', function(message) {
        showMessage(JSON.parse(message.body));
    });

    // 4. 개인 메시지 구독 (내 ID 기준)
    stompClient.subscribe('/queue/private/' + myId, function(message) {
        showPrivateMessage(JSON.parse(message.body));
    });
});

// 5. 메시지 발행
stompClient.send('/app/chat.send', {}, JSON.stringify({ content: '안녕하세요' }));

// 6. 연결 종료
stompClient.disconnect();
```

## 7. 관련 기술 비교

| 기술 | 역할 | 주요 사용처 |
|------|------|-----------|
| **WebSocket** | 서버 ↔ 클라이언트 실시간 양방향 통신 | 채팅, 알림, AI 스트리밍 |
| **STOMP** | WebSocket 위의 메시지 프로토콜 (규칙 정의) | 채팅방, 실시간 알림 |
| **SockJS** | WebSocket 불가 환경의 HTTP 대체 라이브러리 | 브라우저 호환성 보장 |
| **Kafka** | 서버 간 대규모 메시지 비동기 분산 처리 | MSA 이벤트 처리, 크롤링 데이터 보관 |
| **Redis** | 인메모리 빠른 데이터 저장·조회 | 캐시, 세션, AI 대화 내용 저장 |

> Kafka는 메시지 손실 없이 보관하는 특성으로 크롤링 데이터 수집에도 활용된다.  
> Redis는 AI(LLM)에서 대화 내용을 인메모리에 빠르게 저장·조회하는 용도로 많이 사용된다.

### 배운 점
- WebSocket 단독으로는 메시지 라우팅 규칙이 없어 복잡한 채팅 구현이 어렵고, STOMP를 사용하면 `/topic` / `/queue` 목적지 기반으로 전체·개인 전송을 명확하게 구분할 수 있음을 이해함
- SockJS는 WebSocket이 지원되지 않는 환경에서 HTTP 기반으로 자동 대체해주는 폴백 라이브러리로, 브라우저 호환성을 위해 함께 사용함을 이해함
- Kafka와 Redis는 WebSocket과 함께 사용하면 대규모 실시간 서비스를 구성할 수 있는 기술이며, AI 서비스에서 대화 내용 저장에 Redis가 많이 활용된다는 확장 방향을 이해함
