## 1. SecurityFilterChain 구성

Spring Security 6부터 `SecurityFilterChain` Bean을 직접 정의해서 보안 설정을 구성한다.  
XML 방식(`<http>`)에서 Java Config 방식으로 전환되었으며, **람다 기반 DSL**로 작성한다.

```java
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())
            .authorizeHttpRequests(auth -> auth /* URL 권한 설정 */)
            .formLogin(login -> login /* 로그인 설정 */)
            .logout(logout -> logout /* 로그아웃 설정 */)
            .rememberMe(me -> me /* 자동 로그인 설정 */);

        return http.build();
    }
}
```

## 2. URL별 권한(인가) 설정

### 1) 권한 표현식

| 표현식 | 의미 |
|--------|------|
| `permitAll()` | 비로그인 포함 누구나 접근 가능 |
| `denyAll()` | 모두 접근 거부 (403) |
| `authenticated()` | 로그인한 사용자만 |
| `hasRole("ROLE_ADMIN")` | 특정 권한 보유자만 |
| `hasAnyRole("ROLE_ADMIN","ROLE_USER")` | 여러 권한 중 하나 이상 |

### 2) URL 패턴 설정

```java
.authorizeHttpRequests(auth -> auth
    // 관리자 전용
    .requestMatchers("/admin/**").hasRole("ROLE_ADMIN")
    // 로그인 회원 전용 (마이페이지, 댓글 등)
    .requestMatchers("/mypage/**").hasRole("ROLE_USER")
    .requestMatchers("/board/write", "/board/update").authenticated()
    // 누구나 접근 가능
    .requestMatchers("/login", "/member/**", "/board/**").permitAll()
    // 나머지 요청은 로그인 필요
    .anyRequest().authenticated()
)
```

> ⚠️ `requestMatchers`는 **위에서부터 순서대로 매칭**되므로 구체적인 패턴을 먼저 선언해야 한다.

### 3) CSRF 설정

```java
.csrf(csrf -> csrf.disable())
```

- **CSRF** : 인증된 사용자의 쿠키·세션을 이용해 위조 요청을 보내는 공격
- 일반 웹(세션 기반) : CSRF 활성화 권장
- REST API(JWT) : 쿠키를 사용하지 않으므로 비활성화해도 무방

## 3. 로그인(인증) 처리

```java
.formLogin(login -> login
    .loginPage("/member/login")                        // 커스텀 로그인 페이지
    .loginProcessingUrl("/member/login")               // form action URL (Security 자동 처리)
    .usernameParameter("userid")                       // input name 매핑
    .passwordParameter("userpwd")
    .defaultSuccessUrl("/main", false)                 // 로그인 성공 후 이동 URL
    .successHandler(loginSuccessHandler())             // 성공 핸들러 (커스텀 처리)
    .failureHandler(loginFailureHandler())             // 실패 핸들러
    .permitAll()
)
```

**인증 내부 처리 흐름**

```
로그인 요청 (userid / userpwd)
        │
        ▼
Authentication Filter         ← 요청 가로채기
        │
        ▼
Authentication Manager        ← 인증 방법 결정
        │
        ▼
Authentication Provider       ← DB 연동 인증 수행
        │
        ├── UserDetailsService ← DB에서 사용자 정보 조회
        │         └── UserDetails 반환
        │
        └── PasswordEncoder   ← 입력 pw와 DB 암호화 pw 비교
                  │
                  ├── 일치 → SecurityContext에 저장 → 성공 핸들러
                  └── 불일치 → 실패 핸들러
```

## 4. UserDetails - 사용자 정보 구성

Security는 로그인 처리 시 `UserDetailsService`를 통해 DB에서 사용자 정보를 가져온다.  
`UserDetails`를 구현해 Security가 필요로 하는 사용자 정보를 제공한다.

```java
@Override
public UserDetails loadUserByUsername(String username) {
    Member user = memberRepository.findByUserid(username);

    return new User(
        user.getUserid(),    // 1. username (id)
        user.getUserpwd(),   // 2. password (암호화된 비밀번호)
        user.getEnable(),    // 3. 활성화 여부 (false면 로그인 불가)
        true,                // 4. 계정 만료 여부 (true = 만료 안 됨)
        true,                // 5. 계정 잠금 여부 (true = 잠금 안 됨)
        true,                // 6. 비밀번호 만료 여부 (true = 만료 안 됨)
        authorities          // 7. 권한 정보 (ROLE_ADMIN, ROLE_USER 등)
    );
}
```

**UserDetails 7가지 항목**

| 순서 | 항목 | 설명 |
|------|------|------|
| 1 | `username` | 로그인 ID |
| 2 | `password` | 암호화된 비밀번호 |
| 3 | `enabled` | 계정 활성화 여부 |
| 4 | `accountNonExpired` | 계정 만료 여부 |
| 5 | `accountNonLocked` | 계정 잠금 여부 |
| 6 | `credentialsNonExpired` | 비밀번호 만료 여부 |
| 7 | `authorities` | 권한 목록 |

**Controller에서 로그인 사용자 정보 접근**

```java
// Principal : SecurityContext에 저장된 인증 사용자 정보
@GetMapping("/mypage")
public String mypage(Principal principal, Model model) {
    String userid = principal.getName();  // 로그인한 사용자 id
    ...
}
```

## 5. 비밀번호 암호화

Security는 평문 비밀번호 저장을 허용하지 않으며 **BCryptPasswordEncoder**를 권장한다.

```java
@Bean
public BCryptPasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder();
}
```

**BCrypt 특징**

| 특징 | 설명 |
|------|------|
| Salt 자동 적용 | 같은 비밀번호도 암호화할 때마다 다른 해시값 생성 |
| 단방향 암호화 | 복호화 불가 → DB 탈취 시에도 원문 확인 불가 |
| 자동 비교 | Security가 입력 pw와 DB 해시값을 자동으로 비교 |

```java
// 회원가입 시 암호화해서 저장
String encoded = passwordEncoder.encode(rawPassword);

// 로그인 시 비교 (Security 내부에서 자동 처리)
passwordEncoder.matches(rawPassword, encodedPassword);
```

## 6. 로그아웃 처리

```java
.logout(logout -> logout
    .logoutUrl("/member/logout")         // 로그아웃 요청 URL
    .invalidateSession(true)             // 세션 무효화
    .deleteCookies("JSESSIONID")         // 세션 쿠키 삭제
    .logoutSuccessUrl("/main")           // 로그아웃 후 이동 URL
)
```

- 로그아웃 시 SecurityContext를 비우고 세션을 무효화
- `deleteCookies("remember-me")` : 자동 로그인 쿠키도 함께 삭제 가능

## 7. 자동 로그인 (Remember-Me)

로그인 유지 기능으로, 브라우저를 닫아도 **쿠키에 인증 토큰을 저장**해 자동 로그인을 처리한다.

```java
.rememberMe(me -> me
    .rememberMeParameter("remember-me")      // 체크박스 name 값
    .tokenValiditySeconds(60 * 60 * 24 * 7) // 유효 기간 (7일)
    .userDetailsService(userDetailsService)  // 사용자 조회 서비스
    .key("secretKey")                        // 토큰 생성 암호화 키
)
```

**자동 로그인 처리 흐름**

```
로그인 시 체크박스 체크
        │
        ▼
Remember-Me 쿠키 발급 (암호화된 토큰)
        │
        ▼
브라우저 재방문 / 세션 만료
        │
        ▼
쿠키의 토큰 검증 → UserDetailsService로 사용자 조회
        │
        ├── 유효 → 자동 로그인 처리 (SecurityContext 복원)
        └── 만료 / 무효 → 로그인 페이지로 이동
```

```html
<!-- 로그인 폼에 체크박스 추가 -->
<input type="checkbox" name="remember-me"> 로그인 유지
```

## 8. 로그인 성공 / 실패 핸들러

기본 동작 외에 커스텀 처리가 필요할 때 핸들러를 구현한다.

```java
// 로그인 성공 핸들러
public class LoginSuccessHandler implements AuthenticationSuccessHandler {
    @Override
    public void onAuthenticationSuccess(HttpServletRequest request,
            HttpServletResponse response, Authentication auth) throws IOException {

        // auth.getName() : 로그인한 사용자 id
        // auth.getAuthorities() : 권한 목록
        // 권한에 따라 다른 페이지로 이동
        if (auth.getAuthorities().stream()
                .anyMatch(a -> a.getAuthority().equals("ROLE_ADMIN"))) {
            response.sendRedirect("/admin/main");
        } else {
            response.sendRedirect("/main");
        }
    }
}

// 로그인 실패 핸들러
public class LoginFailureHandler implements AuthenticationFailureHandler {
    @Override
    public void onAuthenticationFailure(HttpServletRequest request,
            HttpServletResponse response, AuthenticationException ex) throws IOException {
        response.sendRedirect("/member/login?error=true");
    }
}
```

## 9. 전체 보안 흐름

```
클라이언트 요청
        │
        ▼
SecurityFilterChain
        │
        ├── CSRF 검증 (활성화 시)
        ├── Remember-Me 쿠키 확인 → 자동 로그인 처리
        │
        ▼
URL 권한 검사 (authorizeHttpRequests)
        │
        ├── 권한 없음 → 403 / 로그인 페이지로 redirect
        │
        ▼
로그인 요청인 경우 → formLogin 처리
        │
        ├── UserDetailsService → DB 조회
        ├── PasswordEncoder → 비밀번호 비교
        │
        ├── 성공 → SecurityContext 저장 → 성공 핸들러
        └── 실패 → 실패 핸들러
        │
        ▼
인증 완료 → DispatcherServlet → Controller
```

## 💡 Note

### 오늘 한 일
- SecurityFilterChain 람다 기반 구성 학습
- URL별 접근 권한 설정 (permitAll / authenticated / hasRole) 실습
- UserDetailsService / UserDetails 구현 학습
- BCryptPasswordEncoder 암호화 적용 학습
- Remember-Me 자동 로그인 설정 학습
- 로그인 성공 / 실패 핸들러 구현 학습

### 배운 점
- UserDetails의 7가지 항목 중 `enabled` / `accountNonLocked` 등을 활용하면 단순 로그인 차단 외에도 계정 정지·잠금·만료 등 세밀한 인증 제어가 가능함을 이해함
- BCrypt는 같은 비밀번호도 매번 다른 해시값을 만들어 Rainbow Table 공격을 방어하며, Security가 `matches()`로 자동 비교해주므로 개발자가 직접 복호화할 필요가 없음을 이해함
- Remember-Me는 세션이 만료되어도 쿠키에 암호화된 토큰을 저장해 자동 로그인을 처리하며, 로그아웃 시 해당 쿠키도 함께 삭제해야 완전한 로그아웃이 됨을 이해함
- 로그인 성공 핸들러에서 권한(ROLE_ADMIN / ROLE_USER)에 따라 이동 페이지를 다르게 분기하는 패턴이 실무에서 자주 쓰임을 이해함
