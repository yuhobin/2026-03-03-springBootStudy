## 1. 프로젝트 개요

**Course(강의/과정)** 와 **Question(문제)** 데이터를 Vector로 변환해 PostgreSQL에 저장하고,  
이를 기반으로 **특정 주제 자동 문제 출제** 및 **자동 채점** 기능을 구현하는 Spring AI RAG 시스템

- 현재 단계 : Oracle 원본 데이터 → Embedding → pgVector 저장 완료
- 다음 단계 : 저장된 Vector 기반 문제 출제 / 채점 AI 기능 구현 예정

## 2. 전체 구현 목표

```
[현재 완료]
Oracle DB (Course, Question, Options)
        │
        ▼
Content 문장 생성 → Chunk 분할 → EmbeddingModel
        │
        ▼
PostgreSQL + pgVector 저장 ✅

[구현 예정]
사용자 입력 (주제 / 과목명)
        │
        ▼
Vector 유사도 검색 → 관련 Course 추출
        │
        ▼
AI (Gemini) → 관련 Question 자동 출제
        │
        ▼
사용자 답변 제출
        │
        ▼
Options 벡터 비교 → 자동 채점 / 정답 해설 제공
```

## 3. RAG 기반 Vector 저장 구조

### 1) RAG에서 Vector 저장이 필요한 이유

```
[일반 AI 문제 출제]
주제 입력 → AI가 학습 데이터 기반으로 임의 문제 생성
→ 실제 강의 내용과 무관한 문제가 나올 수 있음

[RAG 기반 문제 출제]
주제 입력 → Vector 검색 → 실제 Course 내용 추출
         → AI가 Course 내용 기반으로 문제 생성
→ 강의 내용에 맞는 정확한 문제 출제 가능
```

### 2) 두 가지 Vector 저장 대상

| 저장 대상 | 용도 |
|---------|------|
| **Course Vector** | 주제 입력 시 관련 강의 검색 → 문제 출제 컨텍스트 제공 |
| **Question Vector** | 유사 문제 검색 / 답변과 정답 의미 비교 → 자동 채점 |

## 4. 데이터 구조 설계

### 1) Oracle 원본 테이블

```
Course (강의/과정)
  ├── course_id    PK
  ├── title        강의명
  ├── description  강의 설명
  └── category     분류

Question (문제)
  ├── question_id  PK
  ├── course_id    FK → Course
  ├── content      문제 내용
  └── answer       정답

Options (지문)
  ├── option_id    PK
  ├── question_id  FK → Question
  ├── option_text  지문 내용
  └── is_correct   정답 여부
```

### 2) PostgreSQL Vector 테이블

```sql
-- Course Vector 테이블
CREATE TABLE course_vector (
    id          SERIAL PRIMARY KEY,
    course_id   INT,           -- Oracle Course FK
    content     TEXT,          -- 강의명 + 설명 청크
    embedding   vector(768)    -- Gemini Embedding 벡터
);

-- Question Vector 테이블
CREATE TABLE question_vector (
    id          SERIAL PRIMARY KEY,
    question_id INT,           -- Oracle Question FK
    course_id   INT,           -- 어떤 강의의 문제인지
    content     TEXT,          -- 문제 + 지문 청크
    embedding   vector(768)
);
```

## 5. Vector 데이터 저장 흐름

### 1) Course Vector 저장

```
Oracle : Course 데이터 전체 조회
        │
        ▼
Content 문장 생성
        │  "강의명: Java 기초 | 설명: 객체지향 프로그래밍... | 분류: 프로그래밍"
        ▼
Chunk 분할 (긴 설명 텍스트 분할 + Overlap으로 문맥 유지)
        │
        ▼
EmbeddingModel (Gemini API)
        │  String → float[] 벡터 변환
        ▼
PostgreSQL course_vector 저장
```

### 2) Question Vector 저장

```
Oracle : Question + Options 데이터 조회
        │
        ▼
Content 문장 생성
        │  "문제: 다음 중 OOP의 특징이 아닌 것은?
        │   ① 캡슐화 ② 상속 ③ 컴파일 ④ 다형성"
        ▼
EmbeddingModel (Gemini API)
        │  String → float[] 벡터 변환
        ▼
PostgreSQL question_vector 저장
```

### 3) Content 문장 생성 코드 구조

```java
// Course Content 생성
private String createCourseContent(CourseVO course) {
    return new StringBuilder()
        .append("강의명: ").append(course.getTitle()).append(" | ")
        .append("설명: ").append(course.getDescription()).append(" | ")
        .append("분류: ").append(course.getCategory())
        .toString();
}

// Question Content 생성 (문제 + 지문 포함)
private String createQuestionContent(QuestionVO question, List<OptionsVO> options) {
    StringBuilder sb = new StringBuilder();
    sb.append("문제: ").append(question.getContent()).append("\n");

    for (int i = 0; i < options.size(); i++) {
        sb.append((i + 1)).append(". ").append(options.get(i).getOptionText()).append("\n");
    }
    return sb.toString();
}

// Embedding 후 PostgreSQL 저장
float[] vector = embeddingModel.embed(content);

CourseVectorVO vo = CourseVectorVO.builder()
    .courseId(course.getCourseId())
    .content(content)
    .embedding(vector)
    .build();

mapper.insertCourseVector(vo);
```

### 4) Chunk & Overlap 적용

긴 강의 설명은 그대로 Embedding하면 의미가 희석되므로 분할 처리

```
Course 설명 (3,000자)
    ├── Chunk 0 : 0 ~ 999자
    ├── Chunk 1 : 800 ~ 1,799자   ← Overlap 200자 (문맥 유지)
    └── Chunk 2 : 1,600 ~ 2,450자
```

### 2) 저장된 Vector 데이터 확인

```sql
-- Course Vector 저장 확인
SELECT id, course_id, content,
       LEFT(embedding::text, 50) AS embedding_preview  -- 벡터 앞 50자만 미리보기
FROM course_vector
LIMIT 10;

-- Question Vector 저장 확인
SELECT id, question_id, course_id, content
FROM question_vector
LIMIT 10;

-- 저장된 벡터 수 확인
SELECT COUNT(*) FROM course_vector;
SELECT COUNT(*) FROM question_vector;
```

### 3) Vector 데이터 확인 시 주의사항

- `embedding` 컬럼은 수백~수천 개의 float 값으로 구성되어 DBeaver에서 전체 출력 시 매우 길게 표시됨
- `LEFT(embedding::text, 50)` 으로 일부만 미리보기 하거나 `content` 컬럼으로 어떤 데이터가 저장됐는지 확인
- 저장 후 `COUNT(*)`로 예상한 개수가 맞게 들어왔는지 반드시 검증

### 4) 유사도 검색 테스트

```sql
-- 특정 벡터와 가장 유사한 Course 검색 테스트
SELECT course_id, content,
       embedding <=> (SELECT embedding FROM course_vector WHERE id = 1) AS distance
FROM course_vector
WHERE id != 1
ORDER BY distance ASC
LIMIT 5;
```

- DBeaver에서 vector 컬럼 전체를 출력하면 수천 개의 float 값이 나오므로 `LEFT(embedding::text, 50)` 으로 미리보기하고 `content`와 `COUNT(*)`로 데이터 적재 검증하는 패턴이 유용함을 이해함
