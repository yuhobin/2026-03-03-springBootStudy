## 1. TanStack Query 개요

**서버 데이터를 가져오고 캐싱·동기화하는 React 전용 라이브러리**

- React 상태와 서버 데이터를 자동으로 동기화
- Next.js에서도 구조 변경 없이 사용 가능
- 오픈소스 그룹에서 관리 (지속적 업데이트)

**장점**

| 특징 | 설명 |
|------|------|
| 자동 캐싱 | 동일 요청 시 서버 재호출 없이 캐시 데이터 반환 |
| 로딩 / 에러 관리 | `isLoading`, `isError` 상태 자동 제공 |
| 중복 코드 감소 | 여러 컴포넌트에서 같은 데이터 공유 가능 |
| 자동 재요청 | 화면 재포커스, 네트워크 재연결 시 자동 갱신 |
| 데이터 갱신 자동화 | Invalidate로 INSERT/DELETE 후 자동 목록 갱신 |

**단점**

- 용어가 많아 학습 초기 진입 장벽이 있음
- 단순한 프로젝트에서는 오버스펙
- 서버 상태(Server State)와 클라이언트 상태(Client State) 구분이 처음엔 어려움

## 2. 동작 흐름

```
React 컴포넌트 → useQuery() 호출
        │
        ▼
Query Key 확인 (캐시 식별자)
        │
        ▼
캐시 존재 여부 확인
        │
        ├── Yes → 캐시 데이터 즉시 반환 (서버 요청 없음)
        │
        └── No
               │
               ▼
           axios 실행 → Spring Boot / NodeJS
               │
               ▼
           응답 데이터 수신
               │
               ▼
           캐시에 저장 (Query Key로 구분)
               │
               ▼
           화면 출력 (React 상태 자동 갱신)
```

---

## 3. 핵심 개념

| 개념 | 설명 |
|------|------|
| **Query** | 서버에서 데이터 조회 (SELECT) → `useQuery` |
| **Mutation** | 서버 데이터 변경 (INSERT / UPDATE / DELETE) → `useMutation` |
| **Query Key** | 캐시를 구분하는 식별자. 동일 Key = 동일 캐시 데이터 공유 |
| **Query Function** | 실제 API 호출 함수 (axios / fetch) |
| **Cache** | 서버 응답 데이터를 임시 저장하는 메모리 공간 |
| **Stale** | 캐시 데이터가 오래되었는지 여부. `staleTime`으로 유효 시간 설정 |
| **Refetch** | 서버에서 데이터를 다시 가져오는 동작 |
| **Invalidate** | 캐시를 무효화해 다음 조회 시 서버 재요청 유도 |

## 4. useQuery - 데이터 조회

```typescript
import { useQuery } from '@tanstack/react-query'
import axios from 'axios'

// 기본 사용법
const { data, isLoading, isError } = useQuery({
    queryKey: ['food'],                      // 캐시 식별자
    queryFn:  () => axios.get('/api/food/list').then(res => res.data)
})

// 파라미터가 있는 경우 (상세보기)
const { data: detail } = useQuery({
    queryKey: ['food', no],                  // no가 바뀌면 새로 요청
    queryFn:  () => axios.get(`/api/food/${no}`).then(res => res.data),
    enabled: !!no                            // no가 있을 때만 실행
})
```

**Query Key 패턴**

```typescript
['food']           // 전체 목록
['food', no]       // 특정 ID의 상세
['food', keyword]  // 검색 결과
```

- 동일한 Key → 동일한 캐시 공유 (여러 컴포넌트가 같은 데이터 사용 가능)
- Key가 바뀌면 → 새로운 요청 자동 실행

**상태값 활용**

```tsx
const { data, isLoading, isError, refetch } = useQuery({ ... })

if (isLoading) return <p>로딩 중...</p>
if (isError)   return <p>에러 발생</p>

return (
    <ul>
        {data?.map(item => <li key={item.no}>{item.name}</li>)}
    </ul>
)
```

## 5. useMutation - 데이터 변경

INSERT / UPDATE / DELETE처럼 **서버 데이터를 변경**할 때 사용

```typescript
import { useMutation, useQueryClient } from '@tanstack/react-query'

const queryClient = useQueryClient()

const { mutate: insertFood } = useMutation({
    mutationFn: (newFood) => axios.post('/api/food/insert', newFood),

    onSuccess: () => {
        // INSERT 성공 후 목록 캐시 무효화 → 자동 재조회
        queryClient.invalidateQueries({ queryKey: ['food'] })
    },
    onError: (error) => {
        console.error('저장 실패:', error)
    }
})

// 호출
insertFood({ name: '된장찌개', address: '서울' })
```

**Mutation 흐름**

```
mutate() 호출
    │
    ▼
mutationFn (axios POST/PUT/DELETE)
    │
    ├── 성공 → onSuccess → invalidateQueries → 목록 자동 갱신
    └── 실패 → onError → 에러 처리
```

## 6. 캐시 전략 - Stale / Invalidate / Refetch

### 1) staleTime - 캐시 유효 시간

```typescript
useQuery({
    queryKey: ['food'],
    queryFn: fetchFoodList,
    staleTime: 1000 * 60 * 5  // 5분 동안 캐시 유지 (서버 재요청 안 함)
})
```

- `staleTime: 0` (기본값) → 항상 최신 데이터 확인
- `staleTime: Infinity` → 수동으로 Invalidate하기 전까지 캐시 유지

### 2) invalidateQueries - 캐시 무효화

```typescript
// INSERT / DELETE 후 목록 캐시 무효화
queryClient.invalidateQueries({ queryKey: ['food'] })
// → 다음 렌더링 시 서버에서 최신 목록 자동 재조회
```

### 3) refetch - 수동 재요청

```typescript
const { data, refetch } = useQuery({ ... })

// 버튼 클릭으로 수동 재요청
<button onClick={() => refetch()}>새로고침</button>
```

**캐시 전략 정리**

```
데이터를 자주 변경하지 않음 → staleTime 길게 설정 (성능 최적화)
INSERT / DELETE 후 목록 갱신 → invalidateQueries
실시간으로 최신 데이터 필요 → staleTime: 0 또는 refetch
```

## 7. 기존 방식 vs TanStack Query 비교

```typescript
// ❌ 기존 useEffect + useState 방식
const [list, setList]       = useState([])
const [isLoading, setLoading] = useState(false)
const [error, setError]     = useState(null)

useEffect(() => {
    setLoading(true)
    axios.get('/api/food/list')
        .then(res => setList(res.data))
        .catch(err => setError(err))
        .finally(() => setLoading(false))
}, [])

// ✅ TanStack Query 방식
const { data: list, isLoading, isError } = useQuery({
    queryKey: ['food'],
    queryFn:  () => axios.get('/api/food/list').then(res => res.data)
})
```

| 구분 | useEffect + axios | TanStack Query |
|------|------------------|----------------|
| 로딩 상태 | 직접 관리 | `isLoading` 자동 제공 |
| 에러 상태 | 직접 관리 | `isError` 자동 제공 |
| 캐싱 | ❌ 없음 | ✅ 자동 캐싱 |
| 중복 요청 방지 | 직접 구현 | ✅ 자동 처리 |
| 코드량 | 많음 | 줄어듦 |
| INSERT 후 목록 갱신 | 수동으로 `setList` | `invalidateQueries` 1줄 |

### 오늘 한 일
- TanStack Query 핵심 개념 (Query / Mutation / Cache / Stale / Invalidate) 학습
- useQuery로 서버 데이터 조회 및 isLoading / isError 상태 활용 학습
- useMutation으로 INSERT 후 invalidateQueries 자동 목록 갱신 실습
- staleTime 설정으로 캐시 유효 시간 제어 학습

### 배운 점
- TanStack Query가 해결하는 핵심 문제는 기존에 `useState` + `useEffect` + `axios`로 직접 관리하던 로딩·에러·캐싱 코드를 자동화해서 중복을 제거한다는 것을 이해함
- Query Key가 캐시의 식별자 역할을 해서 `['food', no]`처럼 파라미터를 포함하면 no가 바뀔 때마다 자동으로 새 요청이 실행된다는 동작 원리를 이해함
- INSERT / DELETE 후 `invalidateQueries`로 해당 캐시를 무효화하면 목록이 자동으로 갱신되는 방식이 기존의 수동 `setList` 방식보다 훨씬 깔끔함을 이해함
- Redux는 클라이언트 상태(UI 상태, 전역 변수)를 관리하고 TanStack Query는 서버 상태(API 데이터)를 관리하는 역할이 분리된다는 것을 이해함
