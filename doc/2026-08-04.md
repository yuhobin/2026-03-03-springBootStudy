## 1. Thymeleaf 개요

Spring Boot에서 사용하는 서버사이드 템플릿 엔진으로, HTML 파일을 그대로 유지하면서 서버에서 보낸 데이터를 결합해 출력한다.

**JSP vs Thymeleaf 비교**

| 구분 | JSP | Thymeleaf |
|------|-----|-----------|
| 파일 형식 | `.jsp` (Java + HTML 혼합) | `.html` (순수 HTML) |
| 브라우저 직접 열기 | 불가 (서버 필요) | 가능 (정적 파일로 열림) |
| 서버 처리 방식 | 변환(Java → HTML) | 파싱(HTML + Model 결합) |
| 배포 파일 | `.war` (파일 크기 큼) | `.jar` (내장 Tomcat 포함) |
| 사용 환경 | Spring Framework | Spring Boot |

> `.war`는 파일 크기가 크기 때문에 CI/CD 배포 시 속도가 느려질 수 있다.  
> Spring Boot의 `.jar` 방식이 CI/CD 환경에서 더 유리하다.

**동작 순서**

```
브라우저 요청
    │
DispatcherServlet → @Controller → @Service → @Repository → DB
    │
Model 객체에 데이터 담기
    │
Thymeleaf 엔진 (HTML + Model 파싱)
    │
완성된 HTML → 브라우저 출력
```

## 2. 표현식

| 표현식 | 용도 | 예시 |
|--------|------|------|
| `${}` | Model에서 전송한 데이터 출력 (EL과 동일) | `${vo.name}` |
| `*{}` | `th:object`로 선택된 Form 객체의 필드 접근 | `*{name}` |
| `#{}` | properties 파일의 메시지 출력 | `#{title}`, `#{db['driver']}` |
| `@{}` | URL 생성 | `@{/board/insert}` |
| `~{}` | Fragment(레이아웃) 조각 포함 | `~{layout/header}` |

## 3. 디렉티브 (th:)

HTML 태그 안에서 `th:` 접두어로 사용하는 Thymeleaf 전용 명령어

### 1) 데이터 출력

```html
<!-- th:text : 텍스트 출력 (HTML 태그 이스케이프 처리) -->
<p th:text="${vo.name}"></p>
<!-- 인라인 표현식으로도 사용 가능 -->
<p>[[${vo.name}]]</p>

<!-- th:utext : HTML 태그 포함 출력 -->
<!-- model.addAttribute("msg", "<b>Hello</b>") -->
<p th:text="${msg}"></p>   <!-- 출력: Hello (태그 무시) -->
<p th:utext="${msg}"></p>  <!-- 출력: Hello (볼드 적용) -->
```

> ⚠️ `th:utext`는 HTML을 그대로 렌더링하므로 **XSS(크로스 사이트 스크립팅) 취약점** 발생 위험이 있어 사용을 가급적 지양

### 2) 속성 바인딩

```html
<!-- th:value : input 기본값 설정 (수정 폼에서 활용) -->
<input type="text" th:value="${vo.name}">

<!-- th:href : URL 바인딩 + 파라미터 전달 -->
<a th:href="@{/food/detail(no=${vo.no})}">상세보기</a>
<!-- 결과: /food/detail?no=1 -->

<!-- th:src : 이미지, iframe, embed 경로 바인딩 -->
<img th:src="${vo.imgUrl}">
<iframe th:src="${url}"></iframe>
```

### 3) 반복문 - th:each

```html
<tr th:each="vo : ${list}">
    <td th:text="${vo.name}"></td>
</tr>

<!-- status 변수로 반복 상태 접근 -->
<tr th:each="vo, status : ${list}">
    <td th:text="${status.index}"></td>   <!-- 0부터 시작 -->
    <td th:text="${status.count}"></td>   <!-- 1부터 시작 -->
</tr>
```

**status 속성**

| 속성 | 설명 |
|------|------|
| `index` | 0부터 시작하는 인덱스 |
| `count` | 1부터 시작하는 순번 |
| `first` | 첫 번째 요소 여부 (boolean) |
| `last` | 마지막 요소 여부 (boolean) |
| `even` / `odd` | 짝수 / 홀수 여부 (boolean) |

### 4) 조건문 - th:if / th:unless / th:switch

```html
<!-- th:if : 조건이 true일 때 출력 -->
<p th:if="${vo.no > 10}">10 이상</p>

<!-- th:unless : 조건이 false일 때 출력 (th:if의 반대) -->
<p th:unless="${vo.name == '홍길동'}">홍길동이 아닌 경우</p>

<!-- th:switch / th:case : 다중 조건 분기 -->
<div th:switch="${no}">
    <p th:case="1">1번</p>
    <p th:case="2">2번</p>
    <p th:case="3">3번</p>
</div>

<!-- th:selected : select 옵션 선택 상태 -->
<option th:selected="${name == '홍길동'}">홍길동</option>
```

### 5) 레이아웃 - th:insert / th:replace

```html
<!-- 공통 레이아웃 조각(Fragment)을 현재 페이지에 포함 -->
<div th:insert="~{layout/header}"></div>
```

- 공통 헤더·푸터·사이드바를 Fragment로 분리해서 재사용 가능
- JSP의 `<jsp:include>`와 동일한 개념

### 6) 유틸리티 객체

```html
<!-- 날짜 포맷 변환 -->
<span th:text="${#dates.format(today, 'yyyy-MM-dd')}"></span>

<!-- 페이징 숫자 범위 생성 -->
<span th:each="i : ${#numbers.sequence(startPage, endPage)}" th:text="${i}"></span>
```

## 4. Controller 처리 방식

### 1) @Controller vs @RestController

| 구분 | @Controller | @RestController |
|------|------------|----------------|
| 역할 | 화면 이동 (Router) | 데이터 반환 (REST API) |
| 주요 연동 | JSP / Thymeleaf | JavaScript(JSON), Kotlin |
| DispatcherServlet 인식 | 둘 중 하나 있을 때만 동작 | |

### 2) return 타입별 동작

| return 타입 | 동작 | 사용 시점 |
|------------|------|---------|
| `String` (View 이름) | forward → Thymeleaf로 Model 전송 | 화면 이동 + 데이터 전달 |
| `"redirect:/경로"` | redirect → request 초기화 | INSERT / UPDATE / DELETE 후 이동 |
| `void` | 직접 응답 처리 | 파일 다운로드, `@ResponseBody` JSON 전송 |

> redirect 시 `request`가 초기화되므로 Model 데이터는 전달되지 않는다.  
> redirect 후 데이터를 넘겨야 할 경우 `RedirectAttributes` 또는 Cookie를 활용한다.

## 5. Controller 매개변수

매개변수 순서는 관계없으며, 필요한 것만 선언해서 사용한다.

### 1) 사용자 입력 데이터 수신

| 방식 | 어노테이션 | 용도 |
|------|-----------|------|
| 단일 값 | `@RequestParam("파라미터명")` | 일반 데이터 수신 |
| VO 전체 | `@ModelAttribute("vo")` | 여러 값을 VO로 한 번에 수신 |

### 2) 내장 객체

| 객체 | 역할 |
|------|------|
| `HttpServletRequest` | 요청 정보 직접 접근 |
| `HttpServletResponse` | 응답 처리 |
| `HttpSession` | 세션 관리 (STOMP 알림·채팅에서도 활용) |
| `Model` | View로 데이터 전달 |
| `RedirectAttributes` | redirect 시 데이터 전달 |
| `Principal` | Spring Security 로그인 사용자 정보 |

## 6. JPA 메서드 규칙

JPA는 메서드 이름 규칙만으로 SQL을 자동 생성한다.  
Repository 인터페이스에 메서드명만 선언하면 구현 없이 동작한다.

### 1) 기본 메서드

| 메서드 | SQL 역할 |
|--------|---------|
| `findAll()` | `SELECT * FROM 테이블` |
| `findBy컬럼명(값)` | `WHERE 컬럼명 = 값` |
| `findTop5By()` | `WHERE ... ROWNUM <= 5` |
| `findDistinctBy()` | `SELECT DISTINCT` |
| `count()` | `SELECT COUNT(*)` |
| `save(entity)` | `INSERT` / `UPDATE` (id 유무로 자동 판단) |
| `delete(entity)` | `DELETE` |

### 2) 조건 키워드

| 메서드명 규칙 | SQL 변환 |
|-------------|---------|
| `findBy컬럼명Between(a, b)` | `WHERE 컬럼명 BETWEEN a AND b` |
| `findBy컬럼명OrderBy컬럼명Desc()` | `ORDER BY 컬럼명 DESC` |
| `findBy컬럼명Contains(값)` | `WHERE 컬럼명 LIKE '%값%'` |
| `findBy컬럼명StartsWith(값)` | `WHERE 컬럼명 LIKE '값%'` |
| `findBy컬럼명EndsWith(값)` | `WHERE 컬럼명 LIKE '%값'` |

### 3) 예시

```java
// SELECT * FROM food WHERE no = ?
Optional<Food> findByNo(int no);

// SELECT * FROM food WHERE address LIKE '%값%'
List<Food> findByAddressContains(String address);

// SELECT * FROM food ORDER BY no DESC
List<Food> findByOrderByNoDesc();

// SELECT * FROM food WHERE price BETWEEN ? AND ?
List<Food> findByPriceBetween(int min, int max);
```
