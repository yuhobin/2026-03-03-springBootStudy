## 1. Kafka 개요

서버 간 **대량의 이벤트/메시지를 비동기적으로 안정적으로 전달**하는 분산 스트리밍 플랫폼

- **비동기 처리** : 메시지를 보낸 후 응답을 기다리지 않음 → 서비스 간 결합도 감소
- **메시지 보관** : 전달된 메시지를 디스크에 보관 → 장애 발생 시 재처리 가능
- **대용량 처리** : 초당 수백만 건의 메시지 처리 가능

**핵심 사용 상황**

- 여러 서비스에 동일한 이벤트를 동시에 전달해야 할 때
- 서비스 간 직접 통신 대신 느슨하게 연결하고 싶을 때
- 메시지 손실 없이 안정적으로 처리해야 할 때

## 2. 핵심 구성 요소

| 구성 요소 | 역할 |
|---------|------|
| **Producer** | Kafka에 메시지를 보내는 애플리케이션 |
| **Topic** | 메시지를 분류해서 저장하는 공간 (채널 개념) |
| **Partition** | Topic을 물리적으로 나눈 단위 → 병렬 처리 가능 |
| **Consumer** | Kafka에서 메시지를 읽어 처리하는 애플리케이션 |
| **Broker** | Kafka 서버. 메시지를 저장하고 전달 |
| **Consumer Group** | 같은 Topic을 나눠서 처리하는 Consumer 묶음 |

```
Producer
    │  메시지 발행 (send)
    ▼
Topic
    ├── Partition 1
    ├── Partition 2
    └── Partition 3
           │  메시지 소비 (poll)
           ▼
Consumer (Group)
```

## 3. 동작 흐름

**주문 처리 예시**

```
사용자 주문
    │
    ▼
주문 서버 (Producer)
    │  "주문 완료" 이벤트 발행
    ▼
Kafka (Topic: order-topic)
    │
    ├──────────────┬──────────────┐
    ▼              ▼              ▼
재고 서비스      결제 서비스      알림 서비스
(Consumer)     (Consumer)     (Consumer)
```

- 주문 서버는 각 서비스에 직접 요청하지 않고 Kafka에 이벤트 하나만 발행
- 각 서비스는 독립적으로 Kafka에서 메시지를 읽어 처리
- 특정 서비스가 다운되어도 메시지가 보관되어 복구 후 재처리 가능

## 4. Kafka vs 기존 방식 비교

| 구분 | 직접 API 호출 | Kafka |
|------|-------------|-------|
| 통신 방식 | 동기 (응답 대기) | 비동기 (즉시 반환) |
| 서비스 결합도 | 높음 (서로 의존) | 낮음 (독립적) |
| 장애 전파 | 한 서비스 장애 → 전체 영향 | 메시지 보관 후 재처리 |
| 확장성 | 어려움 | Partition 추가로 손쉽게 확장 |
| 메시지 보관 | ❌ | ✅ (설정된 기간만큼 보관) |

## 5. 실무 활용 패턴

**웹 개발에서 자주 사용되는 Kafka 활용 사례**

| 패턴 | 설명 |
|------|------|
| 이벤트 드리븐 | 주문 / 결제 / 배송 등 서비스 간 이벤트 전달 |
| 실시간 알림 | 사용자 활동 → Kafka → 알림 서비스 → Push 발송 |
| 로그 수집 | 애플리케이션 로그를 Kafka로 수집 후 분석 |
| 크롤링 파이프라인 | 수집 데이터를 Kafka에 적재 → 손실 없이 처리 |
| MSA 연동 | 마이크로서비스 간 결합도를 낮추는 메시지 버스 역할 |

**Spring Boot에서 기본 사용 구조**

```java
// Producer : 메시지 발행
@Service
public class OrderProducer {
    @Autowired
    private KafkaTemplate<String, String> kafkaTemplate;

    public void sendOrder(String message) {
        kafkaTemplate.send("order-topic", message);
    }
}

// Consumer : 메시지 소비
@Service
public class StockConsumer {
    @KafkaListener(topics = "order-topic", groupId = "stock-group")
    public void consume(String message) {
        // 재고 차감 처리
    }
}
```

### 배운 점
- Kafka의 핵심 가치는 서비스 간 직접 통신을 없애 **결합도를 낮추고**, 메시지를 보관해 **장애 상황에서도 재처리가 가능**하다는 것임을 이해함
- 한 Topic에 여러 Consumer가 구독할 수 있어 주문 이벤트 하나로 재고·결제·알림 서비스가 독립적으로 동작하는 구조가 MSA의 핵심 패턴임을 이해함
- WebSocket이 클라이언트 ↔ 서버 실시간 통신이라면, Kafka는 서버 ↔ 서버 간 대규모 이벤트 전달로 역할이 다름을 이해함
