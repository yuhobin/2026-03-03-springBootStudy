## 1. Vuex 개요

Vue 3 애플리케이션에서 **컴포넌트 간 공유 데이터를 중앙에서 관리**하는 상태 관리 라이브러리

컴포넌트가 많아질수록 props / emit만으로는 데이터 전달이 복잡해진다.  
Vuex는 공유가 필요한 데이터를 **하나의 중앙 저장소(Store)** 에 모아 모든 컴포넌트가 직접 접근할 수 있게 한다.

**생태계 비교**

| Vue | 상태 관리 | 표준화 프레임워크 |
|-----|---------|--------------|
| Vue 3 | Vuex | - |
| Vue 3 (최신) | Pinia | - |
| React | Redux | Next.js / TanStack Query |
| JSP | MVC | Spring |

> Vue 3에서는 Vuex보다 더 단순한 구조의 **Pinia**가 공식 권장 상태 관리 라이브러리로 자리잡고 있다.

**Vuex의 4가지 핵심 구성 요소**

| 구성 요소 | 역할 |
|---------|------|
| `state` | 공유 데이터를 저장하는 공간 |
| `mutation` | state를 **동기적**으로 변경하는 유일한 방법 |
| `action` | 서버 통신 등 **비동기** 처리 후 mutation에 전달 |
| `store` | state / mutation / action을 모두 포함하는 중앙 저장소 |

## 2. State - 공유 데이터 저장소

모든 컴포넌트가 공유하는 데이터를 한 곳에서 관리한다.

```javascript
const store = createStore({
    state: {
        count: 0,
        food_list: [],      // 목록 데이터
        food_detail: {},    // 상세 데이터
        isLogin: false      // 로그인 여부
    }
})
```

- state가 변경되면 해당 데이터를 사용 중인 **모든 컴포넌트의 UI가 자동으로 갱신**됨
- 컴포넌트에서 `store.state.count` 형태로 접근

**데이터 타입별 초기값 설정 관례**

| 데이터 성격 | 타입 | 초기값 |
|-----------|------|-------|
| 객체 (VO) | Object | `{}` |
| 목록 | Array | `[]` |
| 문자열 / 선택값 | String | `''` |
| 숫자 | Number | `0` |
| 참/거짓 | Boolean | `false` |

## 3. Mutation - 상태 변경

**state를 변경할 수 있는 유일한 방법**으로, 반드시 동기적으로 작성해야 한다.

```javascript
mutations: {
    increment(state) {
        state.count++
    },
    decrement(state) {
        state.count--
    },
    setFoodList(state, data) {
        state.food_list = data   // 서버에서 받아온 데이터로 교체
    }
}
```

- 컴포넌트나 action에서 `store.commit('increment')` 로 호출
- mutation 외부에서 `state.count = 1` 처럼 **state를 직접 변경하면 안 됨**
  → 데이터 변경 추적이 불가능해져 디버깅이 어려워짐

---

## 4. Action - 비동기 처리

서버 통신(Axios 등) 처럼 **비동기 작업을 처리**하고, 결과를 mutation에 전달하는 역할

```javascript
actions: {
    fetchFoodList({ commit }) {
        axios.get('/api/food/list')
            .then(response => {
                // 서버에서 받아온 데이터를 mutation으로 전달
                commit('setFoodList', response.data)
            })
    }
}
```

- 컴포넌트에서 `store.dispatch('fetchFoodList')` 로 호출
- action은 직접 state를 변경하지 않고, **반드시 commit(mutation)을 통해** state를 변경

**mutation vs action 비교**

| 구분 | mutation | action |
|------|---------|--------|
| 처리 방식 | 동기 | 비동기 |
| state 직접 변경 | ✅ 가능 (유일) | ❌ 불가 |
| 서버 통신 | ❌ | ✅ |
| 호출 방법 | `commit('함수명')` | `dispatch('함수명')` |

## 5. 전체 데이터 흐름

```
Component (View)
    │
    │  dispatch('action명')
    ▼
Action                    ← 비동기 처리 (Axios 서버 통신)
    │
    │  commit('mutation명', data)
    ▼
Mutation                  ← 동기적으로 state 변경 (유일한 변경 주체)
    │
    ▼
State                     ← 중앙 공유 데이터 갱신
    │
    ▼
UI 자동 반영              ← state를 사용 중인 모든 컴포넌트 자동 업데이트
```

> 반드시 이 흐름을 지켜야 데이터 변경 이력 추적과 디버깅이 가능하다.  
> action → mutation을 거치지 않고 컴포넌트에서 state를 직접 수정하는 것은 Vuex 사용 원칙에 위배된다.

## 💡 Note

### 오늘 한 일
- Vuex의 핵심 구성 요소 (state / mutation / action / store) 학습
- 컴포넌트 → action → mutation → state 데이터 흐름 학습
- mutation(동기) vs action(비동기) 역할 구분 학습

### 배운 점
- 컴포넌트가 많아질수록 props / emit 방식의 한계가 생기고, Vuex처럼 중앙 저장소를 두는 이유가 데이터 흐름을 단순화하고 예측 가능하게 만들기 위한 것임을 이해함
- mutation만이 state를 변경할 수 있는 유일한 주체라는 원칙이, Vue 컴포넌트에서 자식이 부모 데이터를 직접 수정하지 않고 emit으로 요청하는 원칙과 같은 맥락임을 이해함
- action은 서버 통신 결과를 받아 commit으로 mutation에 넘기는 중간 다리 역할이며, 직접 state를 건드리지 않는다는 점이 핵심임을 이해함
