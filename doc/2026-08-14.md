## 1. 람다식 개요

이름 없는 함수(익명 함수)를 값처럼 전달하는 **함수형 프로그래밍 스타일**

**기존 방식 vs 람다**

| 구분 | 일반 클래스 | 람다 |
|------|-----------|------|
| .class 파일 | 생성됨 | 생성 안 함 |
| 메모리 | 큼 | 작음 |
| 코드 길이 | 김 | 짧음 |
| 가독성 | 높음 | 복잡해지면 낮아짐 |

**기본 문법**

```java
// (매개변수) -> {실행문}
(a, b) -> a + b

// 타입 생략 가능
(int a) -> { ... }   // ❌
(a)     -> { ... }   // ✅

// 매개변수 1개 : 괄호 생략 가능
a -> a + 1

// 실행문 1줄 : 중괄호 + return 생략 가능
(a, b) -> a + b      // { return a + b; } 와 동일
```

> 람다를 사용하면 좋은 경우 : 조건 필터링, 데이터 변환, 반복 처리  
> 사용을 지양하는 경우 : 디버깅이 중요한 코드, 복잡한 비즈니스 로직

## 2. 함수형 인터페이스

람다식은 **함수형 인터페이스**에만 사용 가능하다.

```java
@FunctionalInterface        // 람다 전용 인터페이스 명시
public interface MyFilter {
    boolean check(String s); // 추상 메서드는 반드시 1개만
}
```

- `@FunctionalInterface` : 추상 메서드가 2개 이상이면 컴파일 에러 → 람다용임을 보장
- Java 기본 제공 함수형 인터페이스 : `Predicate<T>`, `Function<T,R>`, `Consumer<T>`, `Supplier<T>`

## 3. Stream API

컬렉션(List, Set 등)의 데이터를 **선언형으로 처리**하는 파이프라인

```
List → .stream() → [중간 연산] → [중간 연산] → 최종 연산
```

**연산 구분**

| 구분 | 연산 | 역할 |
|------|------|------|
| 중간 연산 | `filter` | 조건 검색 (`WHERE`) |
| 중간 연산 | `map` | 데이터 변환 / 필드 추출 |
| 중간 연산 | `sorted` | 정렬 (`ORDER BY`) |
| 중간 연산 | `distinct` | 중복 제거 (`DISTINCT`) |
| 최종 연산 | `forEach` | 반복 출력 |
| 최종 연산 | `collect` / `toList()` | 결과를 List로 수집 |
| 최종 연산 | `count` | 개수 반환 |
| 최종 연산 | `reduce` | 누적 합산 |
| 최종 연산 | `average` | 평균 |
| 최종 연산 | `findFirst` | 첫 번째 요소 반환 |

> 중간 연산은 여러 개 연결 가능, 최종 연산은 1개만 호출 가능  
> 최종 연산이 호출되기 전까지 중간 연산은 실행되지 않음 (지연 평가)

## 4. 주요 연산 정리

### 1) filter - 조건 검색

```java
// ADMIN 권한 사용자만 필터링
List<Member> admins = users.stream()
    .filter(u -> "ADMIN".equals(u.getRole()))
    .toList();
```

### 2) map - 필드 추출 / 데이터 변환

```java
// 이름만 추출
List<String> names = users.stream()
    .map(Member::getName)   // 메서드 참조
    .toList();
```

### 3) distinct - 중복 제거

```java
// 역할(role) 종류만 중복 없이 추출
List<String> roles = users.stream()
    .map(Member::getRole)
    .distinct()
    .toList();
```

### 4) reduce / average - 집계

```java
// 나이 합계
int sum = users.stream()
    .map(Member::getAge)
    .reduce(0, Integer::sum);

// 나이 평균
double avg = users.stream()
    .mapToInt(Member::getAge)
    .average()
    .orElse(0);     // 값이 없을 경우 기본값
```

### 5) 연산 조합

```java
// 30세 이상 사용자 이름을 가나다 순으로
List<String> result = users.stream()
    .filter(u -> u.getAge() >= 30)
    .sorted(Comparator.comparing(Member::getName))
    .map(Member::getName)
    .toList();
```

## 5. Security에서의 활용 예시

람다를 배우는 목적은 **Spring Security와 JWT 코드 작성**에 있다.  
Security 설정 코드가 람다식 기반으로 작성되기 때문에 람다 문법 이해가 선행되어야 한다.

```java
// Spring Security 설정에서의 람다 활용 패턴
http
    .authorizeHttpRequests(auth -> auth
        .requestMatchers("/admin/**").hasRole("ADMIN")
        .requestMatchers("/member/**").permitAll()
        .anyRequest().authenticated()
    )
    .formLogin(login -> login
        .loginPage("/member/login")
        .defaultSuccessUrl("/main")
    )
    .logout(logout -> logout
        .logoutUrl("/member/logout")
        .invalidateHttpSession(true)
    );
```

**권한별 필터링 (Security + Stream 조합)**

```java
// 로그인한 사용자의 권한 목록 추출
List<String> roles = user.getAuthorities().stream()
    .map(GrantedAuthority::getAuthority)
    .toList();
// ["ROLE_ADMIN", "ROLE_USER"]
```

### 배운 점
- 람다식이 .class 파일을 생성하지 않아 메모리가 작고 재사용이 쉽다는 이점을 이해함. 단, 복잡해질수록 가독성이 떨어지므로 적절한 상황에서만 사용해야 함을 이해함
- Stream 중간 연산은 최종 연산이 호출될 때까지 실행되지 않는 지연 평가 방식으로, 불필요한 연산을 줄이는 성능 최적화 원리를 이해함
- 람다를 배우는 이유가 Spring Security 설정 코드에 람다식이 적극 사용되기 때문이며, Security 코드의 `.authorizeHttpRequests(auth -> ...)` 패턴이 함수형 인터페이스를 람다로 구현한 것임을 이해함
