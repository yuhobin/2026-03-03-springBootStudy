## 1. Gradle Build 개요

Gradle은 Spring Boot 프로젝트의 **빌드 자동화 도구**로, 소스코드를 실행 가능한 파일로 조립하는 역할을 한다.

**Gradle Build가 하는 일**

| 단계 | 역할 |
|------|------|
| 소스 컴파일 | `.java` 파일을 `.class`(바이트코드)로 변환 |
| 의존성 관리 | `build.gradle`에 선언된 라이브러리를 자동으로 다운로드·포함 |
| 테스트 실행 | 작성된 테스트 코드 자동 실행 |
| 패키징 | 전체 프로젝트를 하나의 `.jar` 파일로 압축 |

**Maven vs Gradle**

| 구분 | Maven | Gradle |
|------|-------|--------|
| 설정 파일 | `pom.xml` | `build.gradle` |
| 빌드 속도 | 상대적으로 느림 | 빠름 (증분 빌드 지원) |
| 문법 | XML | Groovy / Kotlin DSL |
| Spring Boot 기본 | 선택 가능 | 현재 더 많이 사용 |

> Spring Boot에서 Gradle로 빌드하면 내장 Tomcat이 포함된 **실행 가능한 단독 `.jar`** 파일이 생성된다.  
> 별도 Tomcat 설치 없이 `java -jar` 명령 하나로 서버를 실행할 수 있다는 것이 가장 큰 장점이다.

## 2. Gradle Build 방법

```bash
# 1. 프로젝트 폴더로 이동
cd C:\springBootDev\bootStudy\SpringThymeLeafProject_1

# 2. 프로젝트 빌드 (소스 컴파일 + 의존성 포함 + .jar 생성)
gradlew build

# 3. 빌드 결과물 폴더로 이동
cd build\libs

# 4. 빌드된 .jar 파일로 서버 실행
java -jar SpringThymeLeafProject_1-0.0.1-SNAPSHOT.jar
```

- `gradlew` : Gradle Wrapper. Gradle이 로컬에 설치되지 않아도 프로젝트에 포함된 Gradle로 빌드 가능
- `-DskipTests` 옵션 추가 시 테스트 생략 가능 (`gradlew build -x test`)
- 빌드 결과물은 항상 `build/libs/` 폴더에 생성됨

## 3. Thymeleaf

서버에서 **HTML 파일과 데이터를 결합**해 완성된 HTML을 브라우저에 전달하는 서버사이드 템플릿 엔진  
JSP를 대체하는 Spring Boot의 기본 View 기술이며, 순수 HTML 파일로 작성되어 브라우저에서 바로 열어볼 수 있다.

### 1) 동작 흐름

```
브라우저 요청 (<a>, <form>)
        │
        ▼
DispatcherServlet → @Controller
        │
        ▼
Model에 데이터 담기
        │
        ▼
Thymeleaf 엔진 (HTML + Data 결합)
        │
        ▼
완성된 HTML → 브라우저 출력
```

JSP와 동일한 MVC 흐름이지만, View 처리를 **Thymeleaf 엔진**이 담당한다는 점이 다르다.

### 2) 표현식

| 표현식 | 용도 | 예시 |
|--------|------|------|
| `${변수}` | Model에 담긴 데이터 출력 | `${name}` |
| `@{URL}` | 링크(URL) 생성 | `@{/member/list.do}` |
| `*{변수}` | `th:object`로 선택된 객체의 필드 접근 | `*{userid}` |

### 3) 디렉티브 (th:)

HTML 태그 안에서 `th:` 접두어로 사용하는 Thymeleaf 전용 명령어

| 디렉티브 | 역할 | 대응 개념 |
|---------|------|---------|
| `th:text` | 텍스트 데이터 출력 | `${변수}` |
| `th:each` | 반복 출력 | `v-for` / JSTL `c:forEach` |
| `th:if` | 조건부 출력 (true일 때) | `v-if` |
| `th:unless` | 조건부 출력 (false일 때, `th:if`의 반대) | `v-else` |
| `th:href` | 링크 URL 바인딩 | `:href` |
| `th:src` | 이미지 경로 바인딩 | `:src` |
| `th:value` | input 값 바인딩 | `:value` |
| `th:action` | form action URL 바인딩 | - |

### 4) 유틸리티 객체

`#` 접두어로 사용하는 내장 유틸리티 객체

```html
<!-- 날짜 포맷 변환 -->
<span th:text="${#dates.format(date, 'yyyy-MM-dd')}"></span>

<!-- 숫자 천단위 콤마 (페이징 등) -->
<span th:text="${#numbers.formatInteger(price, 3, 'COMMA')}"></span>
```

### 5) @RequestParam

Thymeleaf 환경에서도 파라미터 수신 방식은 Spring Framework와 동일하다.

```java
@GetMapping("/list")
public String list(@RequestParam String keyword,
                   @RequestParam(required = false) String category,
                   Model model) {
    // required = false : 해당 파라미터가 없어도 오류 없이 null로 처리
}
```

## 4. JPA 개요

**Java Persistence API** — 자바 객체와 DB 테이블을 자동으로 연결해주는 ORM 표준 기술

### 1) 기존 방식 vs JPA

| 구분 | 기존 (MyBatis) | JPA |
|------|--------------|-----|
| SQL 작성 | 개발자가 직접 작성 | 자동 생성 |
| 객체 ↔ 테이블 연결 | Mapper XML / 어노테이션 | `@Entity` 어노테이션 |
| 학습 난이도 | 낮음 | 상대적으로 높음 |
| 유연한 쿼리 | 유리 | 복잡한 쿼리는 추가 작업 필요 |

### 2) 핵심 어노테이션

```java
@Entity             // 이 클래스가 DB 테이블과 매핑됨을 선언
@Table(name="board") // 클래스명과 테이블명이 다를 경우 테이블명 지정
@DynamicUpdate      // 변경된 컬럼만 UPDATE (전체 컬럼 UPDATE 방지)
public class Board {

    @Id             // Primary Key 컬럼 지정
    private Long id;

    private String title;
    private String content;
}
```

| 어노테이션 | 역할 |
|-----------|------|
| `@Entity` | 클래스를 DB 테이블과 매핑 |
| `@Table` | 매핑할 테이블명 직접 지정 (클래스명과 다를 때) |
| `@Id` | Primary Key 컬럼 지정 |
| `@DynamicUpdate` | 수정 시 변경된 컬럼만 UPDATE 쿼리에 포함 |

### 3) 데이터 저장 방식

```java
// MyBatis : SQL 직접 작성
// INSERT INTO board VALUES (...)

// JPA : 객체를 저장하면 SQL 자동 생성
repository.save(boardVO);  // INSERT 자동 실행
```

> JPA는 `save(객체)` 한 줄로 INSERT가 처리되며, 객체의 필드가 자동으로 컬럼에 매핑된다.

### 배운 점
- Gradle Build로 생성된 `.jar` 파일 안에 내장 Tomcat이 포함되어 있어, `java -jar` 하나로 서버가 실행된다는 점이 기존 WAR 배포 방식과 가장 크게 다른 점임을 이해함
- Thymeleaf는 JSP와 MVC 흐름은 동일하지만 순수 HTML 파일로 작성되어 서버 없이 브라우저에서 바로 열어볼 수 있다는 점이 개발 편의성 측면에서 유리함을 이해함
- JPA는 SQL을 직접 작성하지 않고 객체 조작만으로 DB 처리가 가능해 생산성이 높지만, 복잡한 쿼리에서는 한계가 있어 MyBatis와 상호 보완적인 관계임을 이해함
