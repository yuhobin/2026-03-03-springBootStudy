## 1. React 개요

Meta(Facebook)에서 개발한 **UI 전용 프론트엔드 라이브러리**  
반복되는 UI 패턴(인스타그램, 항공사 예약 등)을 컴포넌트로 재사용하기 위해 제작

**장점**

| 특징 | 설명 |
|------|------|
| 화면·서버 완전 분리 | React는 UI만 담당, Spring Boot는 API 서버만 담당 |
| 빠른 화면 갱신 | 가상 DOM(Virtual DOM)으로 변경된 부분만 업데이트 |
| 컴포넌트 재사용 | `<Map>`, `<PageCard>` 등 독립 컴포넌트 단위 개발 |
| 비동기 처리 | 서버 통신과 화면 UI를 완전히 분리해서 처리 |
| 실시간 갱신 | JSON 수신 → state 변경 → 화면 갱신 (전체 새로고침 없음) |

**단점**

- 코드 복잡도가 Vue보다 높음
- **CORS 문제** : React(3000포트)와 Spring Boot(8080포트)가 달라 도메인 크로스 이슈 발생
- Cookie / Session을 자체 지원하지 않아 별도 JS 라이브러리 필요
- API URL과 React 내부 라우터 URL이 충돌하지 않도록 관리 필요

## 2. Vue와의 비교 - 면접 핵심

React / Vue 차이는 면접 단골 질문이다.

| 구분 | React | Vue |
|------|-------|-----|
| 데이터 흐름 | **단방향** | **양방향** (`v-model`) |
| 규모 | 대규모 프로젝트에 적합 | 소규모~중규모에 적합 |
| 상태 관리 | Redux / Next.js | Vuex / Pinia |
| 렌더링 방식 | 클라이언트 사이드 렌더링 | 클라이언트 사이드 렌더링 |
| 가상 DOM | ✅ | ✅ |
| 학습 난이도 | 높음 | 낮음 |
| 문서 갱신 속도 | Vue보다 빠름 | 빠름 |

**렌더링 방식 비교**

```
[JSP / Thymeleaf - 서버 사이드]
요청 → 서버 → HTML 생성 → 브라우저 전체 갱신

[React - 클라이언트 사이드]
요청 → JSON 수신 → state 변경 → 변경된 부분만 갱신 (속도 빠름)
```

**단방향 통신 (React의 핵심)**

```
부모 → 자식 : props로 데이터 전달 (단방향)
자식 → 부모 : 이벤트 콜백으로 전달 (Vue의 emit과 동일한 개념)
전역 공유  : Redux / Next.js (Pinia / Vuex와 동일한 역할)
```

## 3. JSX 문법

**JSX (JavaScript + XML)** : React 컴포넌트의 UI를 표현하는 문법

### 1) 핵심 규칙

```jsx
// 1. 최상위 태그는 반드시 1개
// ❌ 오류
return (
  <div>내용1</div>
  <div>내용2</div>
)

// ✅ 정상 - Fragment로 감싸기
return (
  <>
    <div>내용1</div>
    <div>내용2</div>
  </>
)

// 2. 단독 태그는 반드시 닫기
<input />  <br />  <img />

// 3. 변수 출력 : {} 사용
<p>{name}</p>
<img src={imageUrl} />

// 4. class 대신 className
<div className="container"></div>

// 5. style은 객체로
<div style={{ color: 'red', fontSize: '16px' }}></div>

// 6. HTML 태그 소문자 / 컴포넌트 첫 글자 대문자
<div>  <span>   ← HTML 태그 : 소문자
<Header>  <PageCard>  ← 컴포넌트 : 대문자
```

### 2) 변수 종류

| 종류 | 선언 | 특징 |
|------|------|------|
| 지역변수 | `let`, `const` | 변경해도 화면 미반영 |
| 상태변수 | `useState` | 변경 시 화면 자동 갱신 (재렌더링) |
| 불변 데이터 | `props` | 부모로부터 받은 값, 직접 수정 불가 |

## 4. 핵심 Hooks

React 함수형 컴포넌트에서 상태·생명주기 등을 다루는 내장 함수

### 1) useState - 상태 관리

```jsx
const [name, setName] = useState('홍길동')
//     ↑값    ↑변경함수   ↑초기값

// 초기값 형태
useState(0)        // 숫자
useState('')       // 문자열
useState([])       // 배열 (목록)
useState({})       // 객체 (VO)
useState(false)    // boolean

// 사용 예시
setName('김철수')  // name 변경 → 화면 자동 갱신
```

> 서버에서 받아온 데이터는 반드시 **state**로 관리해야 화면이 갱신됨

### 2) useEffect - 생명주기

Vue의 `mounted()` / `updated()`에 해당하는 Hooks

```jsx
// 마운트 시 1회만 실행 (mounted와 동일)
useEffect(() => {
    axios.get('/api/list').then(res => setList(res.data));
}, [])  // 빈 배열 → 최초 1회만

// 특정 값이 변경될 때마다 실행 (watch와 유사)
useEffect(() => {
    fetchData();
}, [curPage])  // curPage가 바뀔 때마다 재호출
```

**useEffect 주요 사용 상황**

| 용도 | 예시 |
|------|------|
| 서버 데이터 초기 로딩 | `axios.get()` |
| 이벤트 등록 | `addEventListener` |
| 타이머 | `setTimeout` / `setInterval` |
| 외부 API 호출 | Kakao Map, jQuery 등 |

### 3) useMemo / useCallback - 성능 최적화

```jsx
// useMemo : 계산 결과 캐싱 (computed와 동일)
const filteredList = useMemo(() => {
    return list.filter(item => item.name.includes(keyword));
}, [list, keyword]);  // list나 keyword 변경 시에만 재계산

// useCallback : 함수 재생성 방지
const handleClick = useCallback(() => {
    fetchData(curPage);
}, [curPage]);
```

**Vue와 Hooks 대응**

| Vue | React Hooks |
|-----|------------|
| `data()` | `useState` |
| `mounted()` | `useEffect(fn, [])` |
| `watch` | `useEffect(fn, [변수])` |
| `computed` | `useMemo` |

## 5. 컴포넌트 작성 방식

### 1) 함수형 (현재 표준 - 권장)

```jsx
// 방식 1
function Home() {
    const [data, setData] = useState([]);
    return <div>{data.map(item => <p key={item.id}>{item.name}</p>)}</div>;
}

// 방식 2 (화살표 함수)
const Home = () => {
    return <div>Home</div>;
}

// 방식 3 (export 동시 선언)
export default function Home() {
    return <div>Home</div>;
}
```

### 2) 클래스형 (레거시)

```jsx
class App extends Component {
    state = { name: '홍길동' }
    componentDidMount() { /* mounted */ }
    componentDidUpdate() { /* updated */ }
    render() { return <div>{this.state.name}</div>; }
}
```

> 현재는 **함수형 + Hooks**가 표준. 클래스형은 구버전 코드 분석 시 참고

### 3) React 핵심 문법 요약

```jsx
import React, { useState, useEffect } from 'react';  // 1. import
import axios from 'axios';

const Home = () => {                                  // 2. 함수형 컴포넌트
    const [list, setList] = useState([]);             // 3. 상태 관리
    
    useEffect(() => {                                  // 4. 렌더링 후 작업
        axios.get('/api/list')                         // 5. 서버 연동
            .then(res => setList(res.data));
    }, []);

    return (                                           // 6. JSX 반환
        <div className="container">                    // className (class ❌)
            {list.map(item => (                        // {} 안에 JS 표현식
                <p key={item.id}>{item.name}</p>       // key 필수
            ))}
        </div>
    );
};

export default Home;                                   // 7. 외부 공개
```

## 7. 서버 연동 구조

React는 Spring Boot와 **완전히 분리된 구조**로 통신한다.

```
브라우저 (React - port 3000)
        │  axios.get('/api/list')
        ▼
Spring Boot (port 8080)
        │  @RestController → JSON 응답
        ▼
DB (Oracle / PostgreSQL)
```

**CORS 해결 (Spring Boot)**

```java
// Spring Boot에서 React 도메인 허용
@Configuration
public class CorsConfig {
    @Bean
    public WebMvcConfigurer corsConfigurer() {
        return registry -> registry.addMapping("/api/**")
            .allowedOrigins("http://localhost:3000");
    }
}
```

**URL 충돌 방지**

```
React 라우터 URL : /list, /detail, /login
Spring Boot API  : /api/list, /api/detail  ← /api 접두어로 구분
```

### 배운 점
- React의 단방향 데이터 흐름은 Vue의 `v-model` 양방향과 달리, 데이터는 부모 → 자식으로만 흐르고 자식이 변경을 요청할 때는 콜백 함수를 사용한다는 것을 이해함
- `useState`로 선언한 변수만 변경 시 화면이 갱신되며, 일반 `let` 변수는 값이 바뀌어도 화면에 반영되지 않는다는 것이 React 핵심 동작 원리임을 이해함
- `useEffect(fn, [])`는 Vue의 `mounted()`와 동일하고, `useEffect(fn, [변수])`는 `watch`와 유사하다는 점에서 기존 Vue 학습과 자연스럽게 연결됨
- `className`, 단독 태그 닫기, 최상위 태그 1개 규칙 등 JSX가 HTML과 다른 핵심 규칙들을 이해함
