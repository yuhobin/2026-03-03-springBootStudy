## 1. Spring AI & Vector 검색 개요

**Spring AI** : Spring 생태계에서 AI 모델(Embedding, Chat 등)을 쉽게 연동할 수 있는 프레임워크

**Vector 검색이란?**

기존 검색은 키워드가 정확히 일치해야 결과가 나오지만, Vector 검색은 **의미적 유사도**를 기반으로 검색한다.

| 구분 | 기존 검색 (LIKE) | Vector 유사도 검색 |
|------|---------------|----------------|
| 방식 | 문자열 일치 | 의미적 유사도 비교 |
| 검색 예시 | "계란" → "계란" 포함된 것만 | "계란" → "달걀", "에그" 유사 레시피도 검색 |
| 저장 형태 | 문자열 (String) | 실수 배열 (float[]) = 벡터 |
| DB | 일반 RDB | pgVector (PostgreSQL 확장) |

## 3. 핵심 기술 개념

### 1) Embedding (임베딩)

텍스트를 AI가 이해할 수 있는 **실수 배열(벡터)로 변환**하는 과정

```
"닭고기, 감자, 양파"  →  EmbeddingModel  →  [0.12, 0.87, 0.34, ...]
         String                                    float[] (vector)
```

- 의미가 비슷한 텍스트일수록 벡터 공간에서 **가까운 위치**에 존재
- 저장할 때 사용한 Embedding 모델과 검색할 때 사용하는 Embedding 모델은 **반드시 동일**해야 함

### 2) Cosine Distance (코사인 거리)

두 벡터 사이의 유사도를 측정하는 방법

```
distance 값이 작을수록 → 두 벡터가 유사 (의미적으로 가까움)
distance 값이 클수록  → 두 벡터가 다름 (의미적으로 멂)
```

```sql
-- pgVector : Cosine Distance 기반 유사 레시피 검색
SELECT * FROM recipe_vector
ORDER BY embedding <=> #{queryVector}   -- <=> : cosine distance 연산자
LIMIT 5
```

### 3) pgVector

PostgreSQL의 벡터 확장 모듈로, float[] 형태의 벡터 데이터를 저장하고 유사도 검색을 지원한다.

## 4. DB 구조 - Oracle + PostgreSQL

레시피 원본 데이터와 벡터 데이터를 분리해서 관리한다.

```
Oracle DB                    PostgreSQL + pgVector
─────────────                ─────────────────────
recipe (원본)                recipe_vector (벡터)
  ├── recipe_id       ────→    ├── recipe_id (FK)
  ├── recipe_name              ├── content (검색용 텍스트)
  ├── ingredients              ├── embedding (float[] 벡터)
  ├── cooking_method           └── (Cosine Distance 검색)
  └── category
```

**recipe_vector 테이블 역할**

| 컬럼 | 설명 |
|------|------|
| `recipe_id` | Oracle recipe 테이블과 연결 |
| `content` | 레시피 재료 + 조리법을 하나의 문장으로 만든 텍스트 |
| `embedding` | content를 EmbeddingModel로 변환한 float[] 벡터 |

**RecipeVectorVO 빌더 패턴**

```java
RecipeVectorVO vo = RecipeVectorVO.builder()
    .recipeId(100)
    .content("닭고기 200g, 감자 2개, ...")  // 재료+조리법 텍스트
    .embedding(embeddingArray)              // float[] 벡터
    .build();
```

## 5. 전체 동작 흐름

### 1) 벡터 데이터 사전 저장 (초기 1회)

```

        │  재료 + 조리법 → content 문장 생성
        ▼
EmbeddingModel
        │  content → float[] 변환
        ▼
PostgreSQL recipe_vector 테이블에 저장
```

### 2) 사용자 검색 시 (실시간)

```
사용자가 냉장고 재료 선택 (닭고기, 감자, 양파)
        │  재료 목록 → 검색 문장 생성
        ▼
EmbeddingModel
        │  "닭고기, 감자, 양파" → queryVector (float[])
        ▼
PostgreSQL pgVector
        │  저장된 embedding과 queryVector의 Cosine Distance 계산
        │  거리가 작은 순으로 정렬 → LIMIT 5
        ▼
유사 레시피 5개 반환
        │
        ▼
재료 비교 및 충족률 계산
        │
        ▼
Thymeleaf 화면 출력
```

## 6. RecipeVectorService 처리 단계

```java
public List<RecipeResultVO> recommend(List<String> ingredients) {

    // 1. 재료 존재 여부 확인
    if (ingredients == null || ingredients.isEmpty()) return List.of();

    // 2. 검색 문장 생성
    String query = String.join(", ", ingredients);
    // "닭고기, 감자, 양파"

    // 3. EmbeddingModel로 벡터 변환
    float[] queryVector = embeddingModel.embed(query);
    // String → float[]

    // 4. pgVector 유사 검색 (Cosine Distance, Top 5)
    List<RecipeVectorVO> similar = mapper.findSimilarRecipe(queryVector);

    // 5. 레시피별 재료 비교 및 충족률 계산
    return similar.stream().map(recipe -> {
        // content에서 재료 목록 추출
        // 보유 재료와 비교 → AVA(보유) / SHO(부족) / SUB(대체) 분류
        // 충족률 계산 (ingredientRate)
    }).toList();
}
```

**핵심 포인트**

- `EmbeddingModel.embed()` : Spring AI가 제공하는 표준 인터페이스 → 모델 교체 시 코드 변경 최소화
- 저장 시와 검색 시 **동일한 Embedding 모델** 사용 필수 (다르면 벡터 공간이 달라 검색 불가)

## 7. 재료 비교 및 충족률 계산

유사 레시피가 검색된 후, 사용자 보유 재료와 레시피 필요 재료를 비교한다.

**재료 상태 분류**

| 상태 | 코드 | 설명 |
|------|------|------|
| 보유 | `AVA` | 사용자가 가지고 있는 재료 |
| 부족 | `SHO` | 레시피에 필요하지만 없는 재료 |
| 대체 | `SUB` | 없지만 대체 가능한 재료 |

**결과 데이터 구조**

```java
public class RecipeResultVO {
    private String recipeName;          // 레시피명
    private String cookingMethod;       // 조리방법
    private String category;            // 요리 종류
    private String cookingProcess;      // 조리 과정
    private List<String> ingredients;   // 전체 재료 목록
    private List<String> missingIngredients;  // 부족한 재료
    private int ingredientRate;         // 재료 충족률 (%)
}
```

**Thymeleaf 출력 예시**

```html
<!-- 충족률 표시 -->
<span th:text="${recipe.ingredientRate + '%'}">75%</span>

<!-- 부족 재료 표시 -->
<ul>
    <li th:each="item : ${recipe.missingIngredients}"
        th:text="${item}">재료명</li>
</ul>
```

### 배운 점
- 기존 LIKE 검색은 문자가 정확히 일치해야 하지만 Vector 검색은 의미적 유사도 기반이라 "계란"으로 검색해도 "달걀"이 포함된 레시피를 찾을 수 있다는 것을 이해함
- 벡터 데이터를 저장할 때 사용한 Embedding 모델과 검색할 때 사용하는 모델이 반드시 동일해야 하는 이유는, 모델마다 벡터 공간이 달라 다른 모델로 생성한 벡터끼리는 거리 비교가 의미 없기 때문임을 이해함
- Cosine Distance 값이 작을수록 유사도가 높은 것으로, `ORDER BY embedding <=> queryVector LIMIT 5` 패턴이 벡터 검색의 핵심 쿼리임을 이해함
- Oracle(레시피 원본)과 PostgreSQL+pgVector(벡터 데이터)를 분리해서 각 DB의 강점을 살리는 설계 방식을 이해함
