## 1. Pinia 개요

Vue 3 공식 권장 상태 관리 라이브러리로, Vuex의 복잡한 구조를 단순화한 후속 표준이다.

- Vue DevTools와 완벽 연동 → 상태 변화 실시간 추적 가능
- TypeScript 친화적 (타입 추론 자동 지원)
- 여러 Store를 독립적으로 분리해서 관리 가능

```bash
npm install pinia
```

```javascript
// main.js
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'

const app = createApp(App)
app.use(createPinia())
app.mount('#app')
```

## 2. Vuex와 비교

| 구분 | Vuex | Pinia |
|------|------|-------|
| Vue 버전 | Vue 2 / 3 | Vue 3 전용 |
| 상태 | `state` | `state` |
| 동기 변경 | `mutation` | ❌ 없음 (직접 변경) |
| 비동기 처리 | `action` | `action` |
| 구조 복잡도 | 높음 | 낮음 |
| TypeScript | 별도 설정 필요 | 기본 지원 |
| 현재 위치 | 레거시 | Vue 3 공식 표준 |

> Pinia에서는 **mutation이 사라졌다.**  
> state를 action이나 컴포넌트에서 직접 변경할 수 있어 코드가 훨씬 단순해진다.

## 3. Store 구성 요소

| 구성 요소 | 역할 | Vue 인스턴스와 대응 |
|---------|------|-----------------|
| `state` | 공유 데이터 저장 | `data()` |
| `getters` | state를 가공해서 반환 | `computed` |
| `actions` | 상태 변경 / 비동기 처리 | `methods` |

## 4. Store 정의 - Option Store vs Setup Store

### 1) Option Store (Vuex와 유사한 방식)

```javascript
// stores/foodStore.js
import { defineStore } from 'pinia'

export const useFoodStore = defineStore('food', {

    state: () => ({
        foodList: [],
        keyword: ''
    }),

    getters: {
        // keyword로 필터링된 목록 (computed와 동일)
        filteredList: (state) =>
            state.foodList.filter(v => v.name.includes(state.keyword))
    },

    actions: {
        // 서버에서 데이터 로딩 (비동기)
        async fetchFoodList() {
            const res = await axios.get('/api/food/list')
            this.foodList = res.data    // mutation 없이 직접 변경
        },
        // 키워드 변경
        setKeyword(keyword) {
            this.keyword = keyword
        }
    }
})
```

### 2) Setup Store (Composition API 방식 - 더 유연)

```javascript
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useFoodStore = defineStore('food', () => {

    // state → ref
    const foodList = ref([])
    const keyword  = ref('')

    // getters → computed
    const filteredList = computed(() =>
        foodList.value.filter(v => v.name.includes(keyword.value))
    )

    // actions → function
    async function fetchFoodList() {
        const res = await axios.get('/api/food/list')
        foodList.value = res.data
    }

    return { foodList, keyword, filteredList, fetchFoodList }
})
```

| 구분 | Option Store | Setup Store |
|------|-------------|------------|
| 익숙한 경우 | Vuex 사용 경험 있음 | Composition API 학습 후 |
| 유연성 | 낮음 | 높음 |
| TypeScript | 보통 | 최적 |

## 5. 컴포넌트에서 사용하기

```vue
<script setup>
import { useFoodStore } from '@/stores/foodStore'

const store = useFoodStore()

// 초기 데이터 로딩
store.fetchFoodList()
</script>

<template>
    <!-- keyword 양방향 바인딩 -->
    <input v-model="store.keyword" placeholder="검색어 입력">

    <!-- getters로 필터링된 목록 출력 -->
    <div v-for="food in store.filteredList" :key="food.no">
        {{ food.name }}
    </div>
</template>
```

**storeToRefs - 반응성 유지하며 구조분해**

```javascript
import { storeToRefs } from 'pinia'

const store = useFoodStore()

// ❌ 일반 구조분해 : 반응성 깨짐
const { foodList } = store

// ✅ storeToRefs : 반응성 유지
const { foodList, keyword, filteredList } = storeToRefs(store)

// actions는 store에서 직접 구조분해 (ref 아님)
const { fetchFoodList } = store
```

### 배운 점
- Vuex에서 mutation이 있었던 이유는 상태 변경 추적을 위해서였는데, Pinia는 DevTools가 이를 대신하므로 mutation 없이 action에서 state를 직접 변경할 수 있어 구조가 훨씬 단순해짐을 이해함
- `storeToRefs`를 사용하지 않고 구조분해하면 반응성이 깨져 화면이 갱신되지 않는다는 점이 중요한 주의사항임을 이해함
- Pinia의 `state` / `getters` / `actions`가 Vue 인스턴스의 `data()` / `computed` / `methods`와 1:1로 대응된다는 점에서 기존 Vue 학습 내용과 자연스럽게 연결됨
