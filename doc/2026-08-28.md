## 1. Kafka 개요

서버 간 **대량의 이벤트/메시지를 비동기적으로 안정적으로 전달**하는 분산 스트리밍 플랫폼

- **비동기 처리** : 메시지를 보낸 후 응답을 기다리지 않음 → 서비스 간 결합도 감소
- **메시지 보관** : 전달된 메시지를 디스크에 보관 → 장애 발생 시 재처리 가능
- **대용량 처리** : 초당 수백만 건의 메시지 처리 가능

**핵심 사용 상황**

- 여러 서비스에 동일한 이벤트를 동시에 전달해야 할 때
- 서비스 간 직접 통신 대신 느슨하게 연결하고 싶을 때
- 메시지 손실 없이 안정적으로 처리해야 할 때

## 2. 핵심 구성 요소

| 구성 요소 | 역할 |
|---------|------|
| **Producer** | Kafka에 메시지를 보내는 애플리케이션 |
| **Topic** | 메시지를 분류해서 저장하는 공간 (채널 개념) |
| **Partition** | Topic을 물리적으로 나눈 단위 → 병렬 처리 가능 |
| **Consumer** | Kafka에서 메시지를 읽어 처리하는 애플리케이션 |
| **Broker** | Kafka 서버. 메시지를 저장하고 전달 |
| **Consumer Group** | 같은 Topic을 나눠서 처리하는 Consumer 묶음 |

```
Producer
    │  메시지 발행 (send)
    ▼
Topic
    ├── Partition 1
    ├── Partition 2
    └── Partition 3
           │  메시지 소비 (poll)
           ▼
Consumer (Group)
```

**Consumer Group 핵심 원칙**

```
Topic (Partition 3개)
    │
    ├── Consumer Group A (알림 서비스)
    │       ├── Consumer 1 → Partition 1 담당
    │       ├── Consumer 2 → Partition 2 담당
    │       └── Consumer 3 → Partition 3 담당
    │
    └── Consumer Group B (로그 서비스)
            └── Consumer 1 → 모든 Partition 구독
```

- 같은 Group 내 Consumer끼리는 메시지를 **나눠서** 처리 (중복 처리 방지)
- 다른 Group은 같은 Topic을 **독립적으로** 모두 수신 가능

## 3. Kafka vs 기존 방식 비교

| 구분 | 직접 API 호출 | Kafka |
|------|-------------|-------|
| 통신 방식 | 동기 (응답 대기) | 비동기 (즉시 반환) |
| 서비스 결합도 | 높음 (서로 의존) | 낮음 (독립적) |
| 장애 전파 | 한 서비스 장애 → 전체 영향 | 메시지 보관 후 재처리 |
| 확장성 | 어려움 | Partition 추가로 손쉽게 확장 |
| 메시지 보관 | ❌ | ✅ (설정된 기간만큼 보관) |

## 4. 댓글 알림 구현 흐름

### 1) 전체 구조

댓글이 작성되면 게시글 작성자에게 실시간 알림을 전달하는 기능을 Kafka로 구현

```
사용자 A가 댓글 작성
        │
        ▼
CommentController
        │  댓글 DB 저장
        ▼
CommentProducer
        │  Kafka Topic "comment-alarm"으로 메시지 발행
        │  { writer: "A", receiver: "B", content: "댓글 내용", postId: 1 }
        ▼
Kafka Broker (Topic: comment-alarm)
        │  메시지 보관
        ▼
AlarmConsumer (@KafkaListener)
        │  메시지 수신
        │  DB에 알림 저장
        ▼
WebSocket (STOMP)
        │  /queue/alarm/{receiverId} 로 실시간 전송
        ▼
게시글 작성자 B 브라우저 (실시간 알림 수신)
```

### 2) 댓글 알림 메시지 구조

```java
// 알림 메시지 VO
public class AlarmMessage {
    private String writer;    // 댓글 작성자
    private String receiver;  // 알림 받을 사람 (게시글 작성자)
    private String content;   // 댓글 내용 (미리보기)
    private Long postId;      // 원본 게시글 ID
    private LocalDateTime createdAt;
}
```

### 3) Kafka가 필요한 이유 (댓글 알림에서)

```
댓글 저장 요청
    │
    ├── [직접 처리] 댓글 저장 + 알림 전송 + WebSocket 전송 → 응답 지연
    │                                                       댓글 서비스와 알림 서비스 강결합
    │
    └── [Kafka] 댓글 저장 → Kafka 발행 (즉시 반환)
                                │
                            알림 서비스가 독립적으로 처리
                            → 댓글 서비스와 완전히 분리
                            → 알림 서비스 장애 시 댓글은 정상 동작
```

## 5. Spring Boot 구현 코드

### 1) Kafka 설정 (application.yml)

```yaml
spring:
  kafka:
    bootstrap-servers: localhost:9092
    producer:
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.springframework.kafka.support.serializer.JsonSerializer
    consumer:
      group-id: alarm-group
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.springframework.kafka.support.serializer.JsonDeserializer
      properties:
        spring.json.trusted.packages: "*"
```

### 2) Producer - 댓글 작성 시 메시지 발행

```java
@Service
public class CommentProducer {

    @Autowired
    private KafkaTemplate<String, AlarmMessage> kafkaTemplate;

    public void sendCommentAlarm(AlarmMessage message) {
        kafkaTemplate.send("comment-alarm", message);
        // 비동기 → 즉시 반환, 알림 처리는 Consumer가 담당
    }
}

// CommentService에서 호출
@Service
public class CommentService {

    public void saveComment(CommentVO comment) {
        commentMapper.insert(comment);   // 댓글 DB 저장

        // Kafka 메시지 발행 (알림 전송은 비동기로 분리)
        AlarmMessage alarm = new AlarmMessage(
            comment.getWriter(),
            comment.getPostWriter(),   // 게시글 작성자
            comment.getContent(),
            comment.getPostId()
        );
        commentProducer.sendCommentAlarm(alarm);
    }
}
```

### 3) Consumer - 메시지 수신 후 알림 처리

```java
@Service
public class AlarmConsumer {

    @Autowired
    private SimpMessagingTemplate messagingTemplate;  // WebSocket 전송

    @Autowired
    private AlarmMapper alarmMapper;

    @KafkaListener(topics = "comment-alarm", groupId = "alarm-group")
    public void receiveCommentAlarm(AlarmMessage message) {

        // 1. DB에 알림 저장 (마이페이지 알림 목록용)
        alarmMapper.insert(message);

        // 2. WebSocket으로 실시간 알림 전송
        messagingTemplate.convertAndSend(
            "/queue/alarm/" + message.getReceiver(),
            message
        );
    }
}
```

## 6. Kafka + WebSocket 연동

댓글 알림은 Kafka와 WebSocket이 각자의 역할을 맡아 협력하는 구조다.

| 기술 | 역할 | 방향 |
|------|------|------|
| **Kafka** | 서버 → 서버 메시지 전달 (댓글 서비스 → 알림 서비스) | 서버 간 |
| **WebSocket (STOMP)** | 서버 → 클라이언트 실시간 전송 | 서버 → 브라우저 |

```
[서버 구간]        [실시간 구간]
댓글 서비스 → Kafka → 알림 서비스 → WebSocket → 브라우저
```

**클라이언트 WebSocket 구독 코드**

```javascript
// 로그인 후 내 알림 채널 구독
stompClient.subscribe('/queue/alarm/' + myId, function(message) {
    const alarm = JSON.parse(message.body);
    showAlarmBadge(alarm);   // 알림 뱃지 표시
});
```

## 7. 실무 활용 패턴

| 패턴 | 설명 |
|------|------|
| **실시간 알림** | 댓글 / 좋아요 / 예약 완료 → Kafka → WebSocket → 브라우저 |
| **이벤트 드리븐** | 주문 / 결제 / 배송 서비스 간 이벤트 전달 |
| **로그 수집** | 애플리케이션 로그 → Kafka → 분석 시스템 |
| **크롤링 파이프라인** | 수집 데이터 → Kafka 적재 → 손실 없이 처리 |
| **MSA 연동** | 마이크로서비스 간 결합도를 낮추는 메시지 버스 |

### 오늘 한 일
- Kafka 핵심 개념 및 Consumer Group 동작 방식 학습
- Kafka를 활용한 댓글 알림 기능 구현
- Producer(댓글 서비스) → Kafka → Consumer(알림 서비스) → WebSocket 연동 흐름 실습

### 배운 점
- Kafka를 사용하면 댓글 서비스와 알림 서비스를 완전히 분리할 수 있어, 알림 서비스에 장애가 생겨도 댓글 저장은 정상 동작한다는 것을 직접 구현하며 이해함
- Consumer Group 내에서는 Partition 단위로 메시지를 나눠 처리해 중복 수신을 방지하고, 다른 Group은 같은 Topic을 독립적으로 구독할 수 있다는 설계 원리를 이해함
- Kafka가 서버 간(서버 → 서버) 비동기 메시지 전달을 담당하고, WebSocket이 서버 → 클라이언트 실시간 전송을 담당하는 역할 분리 구조가 실시간 알림 시스템의 핵심 설계 패턴임을 이해함
